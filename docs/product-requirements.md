## 1. 目的と非目標

`repomonk` は、実在するGitHubリポジトリのソースコードを写経し、完了状況を
ファイルツリーで可視化するRust製TUIです。

達成すること:

- GitHubリポジトリまたはローカルパスから、ワンコマンドで写経を開始できる。
- 速度ではなく、打ちながらコードを体に入れる体験を中心にする。
- ファイルとディレクトリの進捗により、リポジトリを塗りつぶす感覚を作る。
- 速度はローカルで計測するが、常時の主要表示にはしない。
- Typing画面の本文を、エディタのような字句レベルの構文色で表示する。

対象外とすること:

- 解説、LSP、定義ジャンプ、補完、ホバー、診断、リネームなどの読解支援や
  エディタ機能。構文色のために言語サーバーを起動することも含む。
- タイムアタック、ランキングなど速度を競う機能
- 効果音、BGM、マルチプレイ、Web版
- GitHub APIを利用したリポジトリ検索
- 全ターミナルでの動作保証

打鍵イベントと集計結果は外部送信しません。`--purge`により、`repomonk`が
管理するリポジトリキャッシュ、進捗、セッション、統計をすべて削除できることを
必須要件とします。

## 2. 用語

- **ファイル本文**: 写経の最小単位。対象ファイルを正規化した全文。
- **セッション**: ファイルを打ち始めてから完走または「最初からやり直し」を選ぶまでの期間。
  Treeへの中断やアプリ終了ではセッションを確定せず、保存したチェックポイントから続ける。
- **進行モード**: 次に打つファイルを決める戦略。進捗自体はモードに依存しない。
- **場所（Place）**: Home、Tree、Typing、Result。縦1本の階層。Escで1つ戻る。
- **オーバーレイ（Overlay）**: Help、Search、Settings、Stats、Pause、File types、
  Flow。場所の上に開き、閉じると必ず元の場所へ戻る。

## 3. 打鍵

### 3.1 入力判定

- 次に期待される文字と一致した入力だけを受理する。
- 誤入力は本文へ反映せず、カーソルも進めない。
- 誤入力時は期待される文字を150ms赤く表示し、ミス数を1増やす。
- Backspaceを許可する。Backspaceを使っても累積ミス数は減らさない。
- 保持された改行はEnterで入力させる。
- 時間制限とアイドル除外は設けない。
- Escでポーズオーバーレイを開く。`Enter`/`Space`で再開、`r`で最初からやり直し、
  `Esc`/`q`で中断してTreeへ戻る。中断時はファイルを完了扱いにしない。
  Escは常に外側へ進み、Typing → Pause → Tree と1段ずつ抜けられる（D-033）。

### 3.2 正規化と自動入力

- タブを半角スペースへ変換する。既定幅は4とする。
- 写経前に行末の余分な空白を除去する。
- 非ASCII文字を含む行は、正規化時に除外する。
- 行頭インデントは自動挿入し、打鍵数に含めない。
- 括弧の自動補完は無効とする。設定キーは用意するが、MVPでは実装しない。

### 3.3 計測

- リアルタイムKPMは既定で表示しない。
- 結果にはKPM、WPM、正確率、前回比、ミス文字上位5件を表示できる。
- 自動挿入した文字は打鍵数や速度の計算から除外する。
- Typing中に手を止めた時間は経過時間に含める。
- Pause中は経過時間を止める。Typingを離れている時間と同じ扱いとし、再開時に
  再開時刻へ計測の起点をずらす（D-033）。
- Typing中は入力位置と計測値を最大1秒間隔で保存する。Pause、Treeへの中断、
  Ctrl-C、完走では即時保存する。Pause中の強制保存は止まった経過時間を保存する。

## 4. 題材の取得

入力として次を受け付けます。

- `repomonk https://github.com/<owner>/<repo>`
- `repomonk <ローカルパス>`
- ホームの検索モーダルにおける`owner/repo`

リモートリポジトリは、システムの`git`を使ってshallow cloneし、blob filterを
有効にします。認証は既存のcredential helperまたはSSH鍵に委ねます。
キャッシュ先は`~/.cache/repomonk/repos/<owner>__<repo>/`とし、`--refresh`が
ない限り再利用します。

GitHub検索APIは使いません。GitHub URLまたは`owner/repo`以外の文字列は、
ローカルの履歴とキャッシュだけを対象にしたあいまい検索として扱います。

## 5. ファイルの対象判定

ファイルの実効状態は次の3種類です。

- `todo`: 写経対象で未完了。
- `done`: ファイル本文を完走済み。
- `skipped`: 対象外。進捗の分母からも外す。

次のファイルは自動で対象外にします。

- VCS、依存物、生成物、ビルド成果物として既知のディレクトリ配下
- ロックファイルおよび既知の生成ファイルパターン
- バイナリファイル
- 200文字を超える行を含むファイル
- 5,000行を超えるファイル
- `include_tests`が無効な場合のテストファイル
- `include_configs`が無効な場合の設定・ドキュメント・データ記述ファイル
  （`.toml`、`.md`、`.yaml`、`.json`など。HTML / CSSは含まない）
- 正規化後に写経可能な行を1行も残せないファイル

対象外にした理由は保存し、ツリーに表示します。Treeの`x`は選択中のファイル、
またはディレクトリ配下の写経対象をトグルします。`X`は手動上書きを解除し、
自動判定へ戻します。手動上書きは自動判定より常に優先し、refresh後も維持します。

### 5.1 ファイル種別トグル

拡張子（無ければファイル名）単位で、対象・対象外・非表示の3状態を個別に
切り替えられます。種別キーは「拡張子があれば小文字化した`.ext`、無ければ
ファイル名そのもの」（例: `a.rs`→`.rs`、`LICENSE`→`LICENSE`、
`.gitignore`→`.gitignore`）。設定はリポジトリごとにSQLiteへ保存し、
`config.toml`は変更しません。

3状態の意味:

- `included`（対象）: 写経対象として扱う。
- `excluded`（対象外）: 対象外とし、ツリーには理由付きで表示する
  （「file type disabled」）。
- `hidden`（非表示）: `excluded`と同様に対象外とした上で、ツリーから
  完全に取り除く。配下のファイルがすべて非表示のディレクトリも、
  ディレクトリごと非表示になる。`hide_skipped`設定とは独立に効く。

File typesオーバーレイでは`Space`/`Enter`で
`included → excluded → hidden → included`の順に巡回します。

種別ごとのデフォルト値は次のとおりです。

- 拡張子を持たないファイル（`LICENSE`、`Makefile`、`Dockerfile`、
  `.gitignore`のようなドットファイルを含む）は既定で`excluded`とする。
- 拡張子を持つファイルは、そのリポジトリの現在の自動判定で対象になっている
  種別なら`included`、対象外になっている種別なら`excluded`とする。

優先順位は次のとおりです（上が強い）。

1. 手動上書き（`x`/`X`）
2. ファイル種別トグル
3. `include_tests` / `include_configs`による自動判定

ただし`include_tests`によるテスト判定はパスベースの別軸であり、
種別トグルで`included`にしても`tests/`配下などは対象外のままです。

設定が空（そのリポジトリで一度も保存していない）の場合のみ、
リポジトリを開いた直後にFile typesオーバーレイ（Treeの`t`）を自動表示します。
オーバーレイを閉じると変更の有無に関わらずそのリポジトリの設定として保存し、
以後は自動表示しません。設定変更は再スキャンで反映します。単一ファイルを
直接開いた場合は保存済み設定を使わず、常に自動判定のみで対象を決めます。

## 6. 抽出

### 6.1 ファイル本文の生成

- 対象ファイルごとに正規化済み全文を1つの写経単位として生成する。
- 空行境界や行数上限による分割は行わない。
- ラベルによる行の除外後に行数を判定する。除外行は進捗の分母にも入れない。
- 正規化後の行数が0なら、そのファイルは対象外とする。

### 6.2 行ラベル

tree-sitterはファイルを分割するためではなく、行を次の種別へ分類するために
使います。

- `import`: import、use、require、includeの宣言
- `doc`: ドキュメントコメントやdocstring
- `comment`: その他のコメント
- `code`: 上記以外

既定ではimportを除外、docを採用、通常コメントを除外します。対応パーサがない
言語は正規表現へフォールバックします。

Tier 1はRust、TypeScript、TSX、JavaScript、Python、Go、Java、C、C++、C#、
Ruby、PHP、Kotlin、Swift、Dart、Bashです。パーサはCargo featureで切り替え、
既定ではすべて有効にします。Dartは対応を確定する前に、パーサのビルド可否と
import・コメントノードの利用可否を検証します。

## 7. 進捗とrefresh

- ファイル完了は、そのファイル本文を完走したかどうかで決める。
- 完了率は「完了または途中入力済みの正規化済み行数合計 / 対象ファイルの正規化済み行数合計」
  とする。途中入力中の現在行は、改行を受理するまで数えない。
- 中断したファイルは保存済みチェックポイントから再開する。カーソル、打鍵数、ミス数、
  累積経過時間を同じセッションとして引き継ぐ。
- チェックポイントを持つファイルはツリーで`◐`を付け、Next行を「Enter で続きから」
  に変える。受理済み行数が0でも「入力途中」として扱う（D-033）。
- Pauseの「最初からやり直し」はチェックポイントを破棄し、未完了セッションを確定して先頭から始める。
- 全ファイルが`done`または`skipped`なら、リポジトリ完了とする。
- 初回スキャンではファイル、正規化本文、依存関係を並列生成する。走査中の
  進捗表示はバックログとする（Prepare画面は置かない。D-016 / D-022）。
- refresh時は、ファイル全体の正規化済み本文のSHA-256で照合する。行番号は使わない。
- 一致するファイル本文は完了を維持する。
- 変更されたファイル本文は完了を解除し、変更マークを表示する。
- 消えたファイルは履歴として残すが、集計から除外する。

## 8. 進行モード

### 8.1 manual

既定のモードです。ユーザーがツリーからファイルを選びます。おすすめはパス順の
未完了ファイル先頭です。

ファイルを選ぶと、チャンク一覧を出さず直接Typingへ入ります。ファイルを完了したら
自動で別ファイルへ移動せず、Resultを表示します。ResultのEnterで次のおすすめを
開始でき、Esc/`t`でTreeへ戻ります。

### 8.2 flow

検出したエントリポイントから、リポジトリ内部のimportを辿って次に打つファイルを
決めます。対応言語はRust、TypeScript / JavaScript、Pythonです。import辺が空、
またはエントリ候補がゼロならmanualへフォールバックします。

- 既定はtop-down DFSとする。
- 兄弟は、本文で束縛名が最初に使われた行の順とする。未使用（`pub mod` だけの
  宣言など）は宣言行の順に落ちる。
- bottom-upを設定可能にする。
- 循環は訪問済みファイルで打ち切る。
- 到達不能な対象ファイルを末尾へパス順で追加する。
- 順番は保存せず、依存関係から毎回計算する。

エントリは次の優先度で自動検出します。先頭が既定です。対象ファイルに無いパスは
候補から落とします。

1. マニフェスト由来（`Cargo.toml` の `[[bin]] path` / `src/main.rs`、
   `package.json` の `"main"` / `"bin"`）
2. 実行入口: `src/main.rs`、`src/bin/*.rs`、`main.go`、`cmd/**/main.go`、
   `__main__.py`、`main.py`、`manage.py`、`app.py`
3. アプリ入口: `src/index.{ts,tsx,js,jsx}`、`src/main.{ts,tsx,js,jsx}`、
   ルート `index.*`、`app/page.tsx`、`pages/index.*`
4. ライブラリ根: `src/lib.rs`、`lib.rs`、`src/mod.rs`
5. グラフ推定: 被import数0かつ到達可能ファイル数が最大（同点はパス浅い順→辞書順）

モードとエントリはリポジトリ単位でSQLiteに保存します。未設定のリポジトリを開くと、
File typesの直後に進め方ダイアログを出します。2回目以降はTreeの`e`で同じダイアログ
を開きます。保存済みエントリが対象外になっていたら自動検出へフォールバックし、
Treeに1行メッセージを出します。

Treeはパス順のまま並べ、flowの順序は行頭の番号と`Tab`（おすすめへジャンプ）で
辿ります。独立した flow bar は置かず、ヘッダの `files in flow` と選択行詳細の
由来（`← importer:line  import文` / `entry point` / 到達不能）と Next 行
（`▸ Next  step N  │  path  │  Enter to start`）に畳みます。ファイル完走後のResultには
次ファイルと由来を出し、Enterは従来どおりおすすめ（flow順の次）を開始します。
ファイル途中で別ファイルへは飛びません。

## 9. 画面と遷移

画面は場所とオーバーレイの2層で構成します（D-022）。

- **場所**: Home → Tree → Typing → Result。縦1本の階層。
- **オーバーレイ**: Help、Search、Settings、Stats、Pause、File types、Flow。どの
  場所からでも開き、閉じると必ず元の場所へ戻る。場所は変わらない。

Splashは場所ではなく、引数あり起動時の演出です。任意キーでスキップし、`q`や
`Esc`でも終了せずスキップに倒します。Prepare画面は置きません。走査中の進捗
表示はバックログです。`--last`は未実装のバックログです。`stats`サブコマンドは
置かず、`S`オーバーレイで代替します。

リポジトリ引数を渡した場合はHomeを省略し、Splash（任意）のあとTreeを開きます。

### 9.1 共通キー（Typing中を除く）

- `Esc`: オーバーレイがあれば閉じる。無ければ1つ戻る。Homeでは何もしない。
  例外はPauseで、TypingへではなくTreeへ抜けます。Escは常に外側へ進み、
  同じキーの連打で必ず外に出られます（D-033）。
- `q`: `Esc`と同義。Homeでのみ終了する。「`q`を押し続ければ必ず出られる」。
  Typing中は本文入力なので、Pauseを経由して`q`でも抜けられます。
- `Ctrl-C`: どこでも即終了。Typing中は現在のチェックポイントを保存してから終了する。
- `?`: Helpを開く。
- `,`: Settingsを開く。
- `S`: Statsを開く。
- `/`: 検索。Homeではリポジトリ検索、Treeではファイル絞り込み。

Homeの`s`（検索）と`c`（設定）はエイリアスとして残します。Homeの`g`はStats
ではなく、リスト先頭への移動です。

### 9.2 場所

**Home**

- `j`/`k`、`↑`/`↓`でRecentを選択する。`g`/`G`で先頭/末尾へ移動する。
- `Enter`で選択中のリポジトリを開く。
- `/`でSearchを開く。`q`で終了する。

**Tree**

写経対象のファイルとディレクトリだけをツリーとして表示します。
開いた直後はすべてのディレクトリを展開し、次に打つファイルへカーソルを置き、
ヘッダ直下の Next 行にも同じ案内を出します。
Enterで写経を開始します。ディレクトリは単一子のチェーンを1行に圧縮します。

ヘッダのゲージ比率は§7どおり行数ベースです。ラベルはファイル数
（`12%  │  3/48 files`、flow時は `files in flow`）です。対象外ファイルは既定で隠し、
`.`で表示/非表示をトグルします。件数は隠しているかどうかに関わらず詳細行右端に出し、
非表示なら `N excluded  │  .`、表示中なら `N excluded shown  │  .` と表記します。

Chrome（リスト以外の固定行）は常に4行です。ヘッダ、Next、詳細、フッタ。
フィルタ入力とメッセージは詳細行の中身を差し替え、ペインは増やしません。
ディレクトリ行は右寄せの8セルミニバー、ファイル行はマークと名前だけです。
進捗の数値は選択中の詳細行へ集約します
（ファイル: `path  │  172 lines  │  31 done`、ディレクトリ: `path/  │  9 files  │  1 done`）。
対象外を表示しているときは行内を `— test` の短ラベル、詳細行に全文理由を出します。

途中ファイルは受理済み改行までを進捗行数とし、完走したファイルだけが`done`になります。

- `j`/`k`、`↑`/`↓`で表示中の行を移動する。対象外を表示しているときは対象外行にも
  カーソルが止まり、そのまま`x`で写経対象へ戻せる。
  `j`/`k`は長押し中のキーリピートで連続移動する。`g`/`G`で先頭/末尾、
  `Ctrl-d`/`Ctrl-u`で半画面スクロールする（実際のリスト高さの半分）。
- `l`/`→`/`Space`で展開、`h`/`←`で折りたたむ。閉じている場合は親へ移動する。
- `Enter`でファイルを開く。ディレクトリでは展開をトグルする。
- `o`ですべてのディレクトリを展開／たたむ。開いた直後は展開済みなので、
  最初の`o`は選択中の行の祖先以外を折りたたむ。たたんだあとに押すと全展開に戻る。
  カーソル位置は維持する。
- `Tab`でおすすめへジャンプする。
- `/`で絞り込み、`n`/`N`で前後の一致へ移動し、`Esc`で解除する。
- `.`で対象外ファイルの表示/非表示をトグルする。セッション限りで、
  `progress.hide_skipped`（§11）は書き換えない。カーソルは同じ行、かつ画面上の
  同じ位置に留まり、レイアウトシフトを起こさない。対象外行を選んだまま隠した
  場合だけ、直上の残っている行へ寄せる。
- `x`で写経対象をトグルする。ディレクトリなら配下を一括トグルする。
- `X`で手動上書きを解除し、自動判定へ戻す。
- `e`で進め方ダイアログを開く（モードとエントリの変更）。
- `t`でFile typesオーバーレイ（§5.1、§9.3）を開く。

**Typing**

現在行を中央に固定し、対象位置と行進捗（現在行 / 総行）を表示します。本文は
ファイル拡張子に応じた字句レベルの構文色で表示します。打鍵済みと未入力は同じ
構文色を保ったまま明るさで区別し、カーソル、ミスフラッシュ、演出は構文色より
優先します。対応する構文がない場合も単色で表示して打鍵を継続できるものとします。

文字、`Enter`、`Backspace`は本文入力だけに使います。制御は`Esc`（ポーズ）と
`Ctrl-C`だけです。`?`もHelpを開かず本文入力になります。

キーヒントはフッタ行を足さず、ステータス行の右端へ`theme::key_hints`で右寄せ
します。左のデータ欄は`field_sep()`のままで、2系統を連結しません（D-033）。

**Result**

完走時だけ表示します。達成を主、速度と正確率を従とします。中断時はResultを
挟まずTreeへ戻ります。

- `Enter`で次のおすすめを開始する。次がなければTreeへ戻り、リポジトリ完了を
  表示する。
- `r`で同じファイルをもう一度開始する。
- `Esc`/`q`でTreeへ戻る。`t`はここでは何もしない。`t`はTreeのFile types専用と
  する（D-033）。

### 9.3 オーバーレイ

**Pause**（Typingの`Esc`）

- `Enter`/`Space`で再開する。
- `r`で最初からやり直す。
- `Esc`/`q`で中断してTreeへ戻る。中断時はResultを挟まない。Treeのカーソルは
  直前に打っていたファイルへ置き、`Enter`で続きから再開できる。
- ポーズ中は経過時間が止まる（§3.3）。その旨を画面に示す。

**Search**

入力を最優先します。移動は`↑`/`↓`と`Ctrl-n`/`Ctrl-p`だけです。`j`/`k`は常に
文字入力です。

**Settings**

現在の場所を背景に残した中央ダイアログとして表示する。

- `j`/`k`で移動、`h`/`l`で値変更、`Enter`/`Space`でトグルする。
- `Esc`/`q`で閉じ、元の場所へ戻る。
- 再スキャン不要な項目（`ui.language`、`fx.*`、`typing.show_live_speed`、
  `typing.syntax_highlight`、`progress.hide_skipped`）は閉じた時点で現在の
  セッションへ即時反映する。
- 再スキャンが必要な項目は行ごとに「次回オープンから」と表示する。

**File types**（Treeの`t`、§5.1）

Typingの`Esc`（Pause）と同様、Treeを背景に残したままの中央ダイアログとして
表示する。

- ファイル数降順・キー昇順で拡張子/ファイル名を一覧し、`[x]`（対象）/
  `[ ]`（対象外）/`[-]`（非表示）で状態を表示する。
- `j`/`k`で移動、`Space`/`Enter`で`included → excluded → hidden`の順に
  巡回する。
- `Esc`/`q`/`t`で閉じる。閉じると変更の有無に関わらずリポジトリ単位で設定を
  保存し、再スキャンして反映する。
- 保存済み設定が空（初回）のときだけ、リポジトリを開いた直後に自動表示する。
- 全種別を対象外/非表示にするなど写経可能なファイルが1つも残らない設定を
  保存しようとした場合は、直前の設定に戻して元のセッションを維持し、Treeに
  エラーを表示する。

**Stats**

現在の場所を背景に残した中央ダイアログとして表示する。

- `j`/`k`、`g`/`G`でスクロールする。
- `Esc`/`q`で閉じ、元の場所へ戻る。

**Help**

現在の場所を背景に残した中央ダイアログとして表示する。現在の場所のキー、
共通キー、記号凡例を表示します。凡例は`✓ done`、`◐ in progress`、`○ todo`、`· skipped`、
ミニバー（ディレクトリ進捗）、`— reason`（対象外の短ラベル）、`▸ Next`、
`—`（flow外）、flow順の番号です。Treeのフッタに出していないキー（`e` / `t` /
`x` / `X` / `g` / `G` / `/` / `.` / `Ctrl-d` / `Ctrl-u`）はここに置きます。
`h`/`l`/`o`/`Tab`もここへ重複して載せます。

**Flow**（Treeの`e`、初回はFile typesの直後。§8.2）

Treeを背景に残したままの中央ダイアログとして、進行モード（flow / manual）と
エントリ候補を1リストで選ばせる。`j`/`k`で移動、`Enter`/`Space`で行を選択、
`Esc`/`q`/`e`で適用して閉じる。import辺が空ならflow行を無効化しmanualを選ぶ。
候補末尾に「ツリーで選択中」を足し、検出漏れのファイルも起点にできる。

### 9.4 表示

- フッターは原則4〜6個、左から「主要アクション → 移動 → 戻る → `?`」の順とする。
  Treeは6個（日本語既定では `Enter 開く`   `j/k 移動`   `h/l 開閉`   `o たたむ`
  `Tab おすすめ`   `? 詳細`。たたんだあとは `o 全展開`。フィルタ中は `Esc 解除`
  `n/N 次へ`   `j/k 移動`   `Enter 開く`   `? 詳細`。英語時は `open` / `move` /
  `fold` / `collapse` / `next file` / `more`、`clear` / `next` / `move` / `open` /
  `more`）。残りのキーはHelpへ集約する（D-030）。
- Typingだけはフッタ行を持たず、ステータス行の右端に `Esc ポーズ`   `Ctrl-C 終了`
  を右寄せする。主要アクションが本文入力そのものでフッタに載らず、`?`も本文入力
  なので、4〜6個の下限と語順はTypingへ適用しない。幅が足りないときはヒントから
  順に落とし、データ欄は削らない（D-033）。
- データ欄（ヘッダ、サマリ、詳細、Typingステータス）の区切りは箱線の `│`、
  キーヒントは空白のみとする。中黒は使わない（D-031、`docs/ui-guidelines.md`）。
- 動詞は言語ごとに固定する。日本語は開く、開始、次へ、再挑戦、最初から、戻る、
  閉じる、終了。英語は`open`、`start`、`next`、`retry`、`restart`、`back`、
  `close`、`quit`（D-029、D-033）。「最初から」は入力を捨てる操作にだけ使い、
  完走したファイルをもう一度開く「再挑戦」と区別する。
- 画面文言の既定は日本語とする。`[ui] language` と Settings で英語へ切り替えられる。
- 現在地を上部に出す。Treeは`owner/repo`、TypingとResultは
  `owner/repo › src/main.rs`とする。

## 10. 演出

演出はカーソル周辺だけに置き、入力処理を遅延させてはいけません。

- カーソルのグローと100〜150msの残光
- 改行時のイナズマ状軌跡と3段階のノーミス強化
- ミス時の連続記録リセット
- ミス時は赤フラッシュのみとし、画面シェイクは行わない
- 入力と描画を分離し、16msティックと差分描画を使う

演出は無効化可能とし、コア機能の正しさには影響させません。

演出プリセットは次の5種類を提供します。`classic`、`blaze`、`smear`、
`ripple`は正解打鍵でカーソルが前進したタイミングにだけ発火し、本文セル上で
完結します。`fireworks`もカーソル移動時の演出は本文セル上で完結し、
追加の重力演出だけがカーソル周辺で停止中にも段階的に変化します。

- `classic`: 残光、改行トレイル、ノーミス強化を使う標準演出
- `blaze`: 前カーソルから現カーソルへ黄〜オレンジの軌跡を引き、本体を強く発光させる演出
- `smear`: 直近数回のカーソル位置を長いシアン軌跡として残す演出
- `ripple`: カーソル位置から広がる同心円状の色波紋
- `fireworks`: 紫白のブレイズ軌跡、放射火花、縦斬り、分岐する稲妻をカーソル移動時に重ね、
  停止中はカーソル周辺の重力井戸・落下粒子・脈動コア・重力波を段階的に表示する演出

`flare`/`ember`は`blaze`、`comet`/`matrix`は`smear`、`pulse`は`ripple`
として設定読み込み時に互換解釈します。

## 11. 設定

設定ファイルは`~/.config/repomonk/config.toml`です。

```toml
[ui]
language = "ja"

[content]
include_imports = false
include_doc_comments = true
include_comments = false
include_tests = false
include_configs = false
tab_width = 4

[typing]
auto_indent = true
auto_close_brackets = false
allow_backspace = true
syntax_highlight = true
show_live_speed = false

[progress]
mode = "manual"
dependency_direction = "top_down"
keep_done_on_refresh = true
hide_skipped = true

[fx]
enabled = true
intensity = "normal"
preset = "classic"
```

`ui.language` はTUIの表示言語です。既定は`ja`。`en`で英語UIへ切り替えます。
欠落時も`ja`です。Settings（`,`）の変更は閉じた時点で現在のセッションへ即時反映します。
CLIの`--help`は英語のままです。SQLiteへ保存する対象外理由などのキーは英語のままにし、
表示だけ翻訳します。写経本文の非ASCII行除外は変えません（D-029）。

`typing.syntax_highlight` はTyping画面の構文色を切り替えます。既定値は`true`で、
無効にしても打鍵判定、進捗、演出には影響しません。

`progress.mode` は、リポジトリ初回の進め方ダイアログにおける既定選択です。
実際の進行モードとエントリはリポジトリ単位でSQLiteに保存します（§8.2）。
`mode = "dependency"` は読み込み時に `flow` として扱います。

`progress.hide_skipped` の既定は `true` で、Tree を開いた時点の初期値として使います。
対象外ファイルをツリーから隠し、件数は詳細行に出します（§9.2）。Tree の`.`は
この設定を書き換えず、セッション限りで表示を切り替えます。

不正な設定値は無視せず、修正方法が分かるエラーを表示します。

## 12. プライバシーと削除

- アナリティクスやテレメトリを実装しない。
- 生の打鍵イベントと集計結果を端末外へ送信しない。
- `--purge`は、明示的な確認後にアプリ管理下のキャッシュと永続データだけを削除する。
- purgeでは、アプリ管理ディレクトリ外へ向くシンボリックリンクを辿らない。
