# 意思決定記録

実装上の重要な判断を追記する文書です。決定を変更する場合、古い記録を消さずに
状態を「置換済み」とし、新しい決定から参照します。

## D-001: MVPは段階リリースではなく縦切りで完成させる

- 状態: 採用
- 日付: 2026-08-11

### 決定

v0.1、v0.2のような細かな初期リリースへ分けず、次の利用ループ全体をMVPとして
一気に実装します。

`URL / ローカルrepo → Tree → Typing → Result → 進捗保存・再開`

### 理由

単一ファイルの写経だけでは、repomonk固有の価値である「実在リポジトリを
塗りつぶす感覚」を評価できないためです。AIエージェントで独立領域を並列実装し、
短い契約確定後に統合します。

### 影響

clone、走査、ファイルツリー、SQLiteはMVPに含めます。一方で体験の横幅を抑える
ため、tree-sitter、dependencyモード、詳細統計、演出はMVP後とします。

## D-002: manualモードでファイル完了後はTreeへ戻る

- 状態: 置換済み（D-012へ。Resultの遷移はD-022で更新）
- 日付: 2026-08-11

### 決定

Resultの`r`は同じファイルに未完了チャンクがある場合だけ次へ進みます。ファイルを
完了した場合は別ファイルを自動開始せず、Treeへ戻します。

### 理由

原典のmanualモードの意図を優先し、ファイルを塗り終えた達成感と次の選択を
ユーザーへ返すためです。

## D-003: MVPの抽出は言語非依存の共通規則を使う

- 状態: 置換済み（D-012へ）
- 日付: 2026-08-11

### 決定

MVPではtree-sitterを導入せず、タブ正規化、行末空白除去、非ASCII行除外、
空行境界、5〜40行分割を全ファイルへ共通適用します。

### 理由

最初の利用ループに必要なのは安定したチャンク生成であり、言語別ラベルは独立して
後から追加できるためです。

## D-004: 生の打鍵列を永続化しない

- 状態: 採用
- 日付: 2026-08-11

### 決定

MVPで永続化するセッション情報は、開始・終了時刻、完了または中断、入力数、
ミス数などの集計に限定します。正解・誤入力を含むキーイベント列そのものは保存
しません。

### 理由

写経アプリのキーイベント列は、実質的にキーロガーと同じ機密性を持ちます。詳細な
統計に不要な生データを最初から保持しないことで、漏えい時の影響とpurge対象を
小さくします。

## D-006: Backspaceは自動インデントを越えられない

- 状態: 採用
- 日付: 2026-08-11

### 決定

行頭の自動挿入インデントは打鍵位置の手前に既に受理済みとし、Backspaceで
削除・後退できない。手動で打った文字だけを1文字ずつ戻せる。

### 理由

自動インデントは打鍵数に含めない前提であり、インデントを手で消し戻す操作は
写経体験を壊すためです。

## D-007: KPM / WPM / 正確率の計算式

- 状態: 採用
- 日付: 2026-08-11

### 決定

- 打鍵数は自動挿入を除く受理文字数とする。
- 正確率 = 打鍵数 / (打鍵数 + ミス数) × 100。分母0のときは100%。
- KPM = 打鍵数 / 経過分。
- WPM = (打鍵数 / 5) / 経過分。
- 経過時間はセッション開始から終了までとし、アイドル除外はしない。

### 理由

MVPで比較可能な単一の定義が必要であり、一般的なタイピング計測に近い式を選んだ。

## D-008: リポジトリ同一性

- 状態: 採用
- 日付: 2026-08-11

### 決定

- GitHub由来: `github:<owner>/<repo>`（小文字化はせず入力正規化後の owner/repo）。
- ローカル: `local:<canonical absolute path>`。単一ファイルもそのファイルの
  canonical path を identity に使う。

### 理由

URLとローカルパスを混同せず、同一キャッシュ／同一DB行へ安定して紐付けるため。

## D-009: 初期SQLiteスキーマ

- 状態: 採用
- 日付: 2026-08-11

### 決定

単一ファイル `repomonk.db` に次の表を置く。マイグレーションは起動時の
`CREATE TABLE IF NOT EXISTS` と `meta.schema_version=1`。

- `repositories`, `repo_files`, `chunks`, `chunk_progress`, `sessions`, `meta`

完了引き継ぎは `chunks.content_hash`（正規化本文のSHA-256）で行う。非activeな
チャンクは集計から除外する。ファイル単位写経では、ファイルあたり常に1件の
activeレコードとする（D-012）。

### 理由

MVPの永続化要件を最小表で満たし、後からALTERで拡張できるため。

## D-010: purge確認と非対話

- 状態: 採用
- 日付: 2026-08-11

### 決定

`--purge` は削除対象パスを表示し、標準入力へ `yes` と入力されたときだけ削除する。
`--yes` を付けた場合は確認を省略する（CI・テスト用）。

### 理由

誤削除を防ぎつつ、自動テストでは対話なしで検証できるようにするため。

## D-011: ファイル内の初期チャンク選択

- 状態: 置換済み（D-012へ）
- 日付: 2026-08-11

### 決定

未完了チャンクが1つなら直接Typingへ入る。複数ならチャンク一覧を出し、先頭の
未完了チャンクを初期選択する。Resultの `r` も同じ規則で次の未完了へ進む。

### 理由

手動モードで余計な画面遷移を減らしつつ、複数チャンクがあるときは選択権を残す。

## D-012: 写経単位をファイル全文とし、進捗は行数で集計する

- 状態: 採用（完走後の場所とResultキーはD-022で更新）
- 日付: 2026-08-11
- 置換: D-002、D-003、D-011

### 決定

- 写経の最小単位はチャンクではなく、対象ファイルの正規化済み全文とする。
- Treeでファイルを選ぶと、チャンク一覧を出さず直接Typingを開始する。
- 空行境界や `min_lines` / `max_lines` による分割は行わない。
- Esc中断ではファイルを完了にせず、次回はファイル先頭から開始する。
- ファイル完了後は別ファイルを自動開始せず、Treeへ戻る。
- 進捗の分母・分子は正規化済み行数とする（完了ファイルの行数合計 /
  対象ファイルの行数合計）。
- refresh時の完了引き継ぎは、ファイル全体の正規化本文SHA-256で行う。
- 永続化は当面 `chunks` 表を流用し、ファイルあたり常に1レコードとする。

### 理由

ユーザーがファイル単位で開いて打つ体験を優先し、チャンク選択の画面遷移をなくす
ためです。進捗の塗りつぶし感は、チャンク個数より行数の方がファイルサイズの差を
反映できるためです。

### 影響

- D-002 / D-011 の「次チャンクへ進む`r`」とチャンク一覧は不要になる。
- D-003の空行境界・5〜40行分割は採用しない。正規化規則自体は維持する。
- 既存DBに複数チャンクがある場合、再スキャンでhash不一致となり完了が落ちうる
  （ローカル進捗の破壊的変更を受け入れる）。

## D-013: 演出とスプラッシュ画面をMVP後の最初の拡張として実装する

- 状態: 採用
- 日付: 2026-08-11

### 決定

- MVP外としていた演出（プロダクト要件§10）と起動時スプラッシュをユーザーの明示的な
  指示により実装する。カーソルグロー、約120msの残光、改行時の輝きスイープ、
  ノーミス3段階強化（閾値30 / 100 / 250打）、ミス時の連続記録リセットを含む。
- 配色はTokyo Nightを既定とし、`Color::Rgb`直指定（truecolor対応ターミナル前提）
  とする。アイコンはNerd Fontを使わず標準Unicode記号のみとする。
- 演出状態（`ui::fx::FxState`）は打鍵エンジンのスナップショット差分から導出し、
  `TypingEngine`には手を入れない。演出はコア機能の正しさに影響しない。
- Home画面は実装せず、起動直後にASCIIロゴのスプラッシュ（キー押下または約2秒で
  Treeへ遷移）を表示する。（→ D-014で撤回。Splashは引数あり起動時のみ）
- 無効化手段はCLIフラグ`--no-fx`に加え、`config.toml`の`[fx]`（D-015）でも制御する。
  `--no-fx`はセッション上書きとして`fx.enabled`より優先する。

### 理由

MVPの利用ループが完成し、写経体験の質を高える視覚要素が次の価値になるためです。
エンジン非依存の差分導出により、演出の追加・無効化が打鍵判定や進捗集計へ影響
しないことをテストで保証できます。

## D-014: Home画面とSearchモーダルを実装する

- 状態: 置換済み（画面役割は維持。キーマップとSettings/Stats/Result遷移はD-022へ）
- 日付: 2026-08-11

### 決定

- `repomonk`（引数なし）はHomeを最初に表示する。自動でTreeへ進まない。
- `repomonk <URL|path>` は仕様どおりHomeを省略し、従来どおりSplash（任意）→ Tree。
- HomeはASCIIロゴ、Recent（完了率バー）、Summary（完了ファイル/チャンク、連続日数）、
  キー `j`/`k`/`Enter`/`s`/`g`/`c`/`q` を持つ（`c`はD-015のSettings）。
- Search（`s`）は外部APIを使わない。`https://github.com/owner/repo` と
  `owner/repo`、およびローカルRecent・キャッシュ名のあいまい一致のみ。
- `g` は達成サマリ画面のみ（草・速度ヒートマップは対象外）。
- ResultのEnterはHomeへ、Esc/`t`/`r`はTreeへ戻る。TreeのEscもHomeへ戻る。
- 引数あり起動時のSplash自動遷移は維持する。

### 理由

タイトル／ホームとしての役割（リポジトリ選択と起動の入口）が欠けると、起動直後に
Treeへ飛ばされて仕様の画面役割とずれるためです。

## D-015: config.toml と TUI Settings

- 状態: 置換済み（D-016へ）
- 日付: 2026-08-12

### 決定

- ユーザー設定は`~/.config/repomonk/config.toml`に永続化する（プロダクト要件§11）。
- Homeの`c`で全画面Settingsを開き、変更は都度保存する。EscでHomeへ戻る。
- 現行ロジックへ結線するキー: `include_tests` / `include_configs` / `tab_width` /
  `auto_indent` / `allow_backspace` / `show_live_speed` / `keep_done_on_refresh` /
  `hide_skipped` / `fx.enabled` / `fx.intensity`。
- tree-sitter依存の行ラベル系（`include_imports`等）、`mode`/`dependency_direction`、
  `auto_close_brackets`は保存可能だがUI上「unsupported」またはlockedとし、挙動は未実装。
- 不正な設定値は起動時に修正方法付きエラーで失敗する。欠落ファイルはデフォルトで動作する。
- 設定変更の反映は次回リポジトリオープン／次回写経開始から（開いているセッションの再走査はしない）。
- `--no-fx`は`config.toml`の`[fx]`より優先するセッション上書き。

行ラベルとdependency設定の結線範囲は、後続のD-016で拡張した。

### 理由

仕様書§8とプロダクト要件§11の設定面を、TUIから変更できる体験として提供するためです。

## D-016: 行ラベルとdependency進行を設定へ結線する

- 状態: 採用（entry と兄弟順は D-025 で置換。完走後の場所はD-022で更新。Prepare非採用は維持）
- 日付: 2026-08-12

### 決定

- `include_imports`、`include_doc_comments`、`include_comments`は、正規化前に
  行ラベルを付けてから除外する。codeとコメントが混在する行はcodeとして残し、
  それ以外はimport、doc、commentの順で分類する。
- 行ラベルはtree-sitterを既定有効にし、Rust、TypeScript、TSX、JavaScript、
  Python、Goを対象にする。パーサが使えない言語または解析に失敗した場合は、
  行頭規則によるフォールバックを使う。
- `progress.mode = "dependency"`では、Rust、TypeScript/JavaScript、Pythonの
  リポジトリ内相対importから依存順を毎回計算する。未解決・外部importは無視し、
  グラフが空の場合はmanualのパス順へフォールバックする。
- entryは被参照数が最多のtypeableファイルを既定とし、Treeで`e`を押すと選択中の
  typeableファイルをセッション内のentryとして再計算する。Prepare画面は追加しない。
- `top_down`はpre-order DFS、`bottom_up`はpost-order DFSとする。importの出現順を
  兄弟順とし、循環は訪問済みで停止し、未到達ファイルはパス順で末尾へ追加する。
- dependency順序はSQLiteへ保存せず、リポジトリを開くたびに再計算する。完了後に
  別ファイルを自動開始せず、完了後は従来どおりTreeへ戻る。
- 上記5キーはSettingsのunsupported表示を外し、`auto_close_brackets`のlocked表示は
  維持する。

### 理由

Settingsに存在する抽出・進行設定を保存だけで終わらせず、既存のScan、Domain、App、
Tree境界へ結線するためです。依存順を保存しないことで、refresh後も現在の本文と
設定から一貫した順序を導出できます。

## D-017: TUI内の演出プリセットを追加する（D-018で置換）

- 状態: 置換済み
- 日付: 2026-08-12

### 決定

- GPUや別ウィンドウは追加せず、ratatuiのセル描画だけで演出を表現する。
- `[fx].preset`で`classic`、`matrix`、`pulse`、`ember`を切り替える。
- `classic`は既存の残光・改行トレイル・ノーミス強化を維持する。
- `matrix`は右端の雨文字と未入力文字の色変化、`pulse`は入力位置からの
  波紋、`ember`はストリーク連動の炎色グローとスパークルを表示する。
- すべてのプリセットで`fx.enabled`、`intensity`、`--no-fx`による無効化を維持し、
  打鍵エンジンと入力処理には演出状態を混入させない。

### 理由

repomonkは端末TUIであり、GPUシェーダーを導入するとウィンドウ管理と描画基盤が
変わるためです。セル描画の範囲に留めることで、現在の操作感とモジュール境界を
保ったまま、派手さの異なる演出を設定から選択できます。

## D-018: 演出をカーソル移動専用プリセットへ再編する

- 状態: 採用
- 日付: 2026-08-12

### 決定

- 演出は正解打鍵によるカーソル前進時だけ発火し、常時動く背景アニメや行末
  ガターは表示しない。
- Ghosttyの`cursor_blaze`に着想を得て、プリセットを`classic`、`blaze`、
  `smear`、`ripple`へ再編する。
- `classic`は既存の残光・改行トレイル・ノーミス強化、`blaze`は前カーソルから
  現カーソルへ黄〜オレンジの軌跡と本体ブルーム、`smear`は長いシアン軌跡、
  `ripple`は同心円状の波紋を担当する。
- 旧設定値`flare`/`ember`は`blaze`、`comet`/`matrix`は`smear`、
  `pulse`は`ripple`として読み込み、保存時は新しい値へ正規化する。

### 理由

演出の主役をカーソル移動に限定することで、本文の可読性と入力への反応を両立し、
PRD §10の「カーソル周辺だけ」という要件を実装上も明確にするためです。

## D-019: Typing本文の構文色にsyntectを使う

- 状態: 採用
- 日付: 2026-08-12

### 決定

- PRDのTyping要件として、本文をファイル拡張子に応じた字句レベルの構文色で
  表示する。
- 構文色の実装には、埋め込み文法を使う`syntect`（TextMate形式）を採用する。
- LSP、semantic token、定義ジャンプ、補完、診断などの言語サーバー機能は追加
  しない。
- Typing開始時に正規化済み本文を一度だけ解析し、文字インデックスごとの色配列
  をUIセッションへ保持する。`TypingEngine`と進捗・永続化層には構文情報を渡さない。
- 未対応言語や解析失敗時は単色へフォールバックし、構文色は設定で無効化できる。
- 打鍵済み・未入力は構文色の色相を維持したまま明るさで区別し、カーソル、
  ミスフラッシュ、既存の演出を構文色より優先する。

### 理由

本文は一つのTypingセッション中に変化しないため、増分解析や言語サーバーの
ワークスペース管理は不要です。syntectなら文法をアプリへ埋め込めるので実行時の
ネットワークや外部プロセスに依存せず、既存の文字単位描画へ色を合成できます。
tree-sitterは行ラベルと依存解析の責務にすでに使っているため、ハイライト用の
クエリやテーマ管理を同じ境界へ持ち込みません。

### 影響

構文色は`ui::highlight`に閉じ、`App`がTyping開始時に呼び出して描画へ渡します。
設定を無効にしても打鍵判定、進捗、演出、セッション保存の結果は変わりません。

## D-020: Ghosttyの花火系シェーダーをfireworksプリセットへ近似する

- 状態: 採用
- 日付: 2026-08-12

### 決定

- Ghosttyの`cursor_blaze`、`sparks`、`slash`、`cursor_lightning`、
  `gravity`を、GPUシェーダーとして移植せず、ratatuiの本文セル色ブレンドで
  `fireworks`プリセットとして近似する。
- `cursor_blaze`は紫白のカーソル軌跡、`sparks`は短寿命の放射ハイライト、
  `slash`は上から下へ掃引する縦ハイライト、`cursor_lightning`はハッシュで
  揺らした分岐線として表現する。
- `gravity`は常時動く背景にはせず、最後のカーソル移動からの経過時間を使って
  カーソル周辺だけを段階的に強化する。0〜2秒は弱い井戸、2〜5秒は粒子を追加し、
  5秒以降は約1.5秒周期の重力波を追加する。
- `fireworks`以外の既存プリセットの挙動と色は変更しない。GPU、別ウィンドウ、
  入力処理への演出状態の混入は引き続き行わない。

### 理由

Ghosttyのシェーダーが持つ移動トレイル、火花、斬撃、稲妻、重力井戸という
視覚的な構成を維持しつつ、repomonkのTUI描画基盤とD-017のGPU禁止を両立する
ためです。セル格子ではピクセル単位のSDFや25本のビームを忠実に再現できないため、
ハッシュ付きの短寿命イベントと近傍セルの強度で視覚的な類似を優先します。

## D-021: include_configsで非プログラミング言語を既定除外する

- 状態: 採用
- 日付: 2026-08-12

### 決定

- `include_configs=false`（既定）では、既存の設定ファイルに加えて、
  MarkdownなどのドキュメントとJSONなどのデータ記述ファイルも自動対象外にする。
- 追加対象外拡張子は`.md`、`.markdown`、`.mdx`、`.rst`、`.txt`、`.adoc`、
  `.asciidoc`、`.json`、`.xml`、`.csv`、`.tsv`とする。
- `include_configs=true`では、これらのファイルも従来どおり写経対象に含める。
- HTML、CSS、SCSSなどのマークアップ／スタイルシートはこの判定では除外しない。
- 既存の`include_configs`キーと設定値は維持し、保存済みSQLiteの旧い対象外理由も
  現行の`ConfigFile`として読み込めるようにする。

### 理由

既定の写経対象をプログラムの実装に集中させつつ、設定やドキュメントを含めたい
ユーザーには既存の設定項目で選択できるようにするためです。HTMLとCSSは画面や
スタイルの実装として扱うため、非プログラミング言語の一律除外には含めません。

## D-022: ナビゲーションと情報設計の再定義

- 状態: 採用（Treeのフッタ件数はD-030で6個へ更新。Pause / Result のキーと
  オーバーレイのEsc規則はD-033で更新）
- 日付: 2026-08-13
- 更新: D-002、D-012、D-014、D-016

### 決定

画面を場所とオーバーレイの2層に分ける。場所はHome → Tree → Typing → Resultの
縦1本だけとし、オーバーレイ（Help / Search / Settings / Stats / Pause）はどの
場所からでも開き、閉じると必ず元の場所へ戻る。

共通キーは次のとおりとする。Typing中は本文入力を優先し、制御は`Esc`（ポーズ）
と`Ctrl-C`だけにする。

- `Esc`: オーバーレイを閉じる。無ければ1つ戻る。Homeでは何もしない。
- `q`: `Esc`と同義。Homeでのみ終了する。
- `Ctrl-C`: どこでも即終了。Typing中は現在のチェックポイントを保存してから終了する。
- `?` Help、`,` Settings、`S` Stats、`/` 検索（Homeはリポジトリ、Treeはファイル）。

Homeの`s`と`c`はエイリアスとして残す。Homeの`g`はStatsではなく先頭移動へ
再割り当てする。

場所ごとの主操作は次のとおりとする。

- Home: `j`/`k`選択、`g`/`G`先頭/末尾、`Enter`で開く、`/`検索、`q`終了。
- Tree: `j`/`k`、`g`/`G`、`Ctrl-d`/`u`、`h`/`l`折りたたみ、`Enter`で開く、
  `Tab`でおすすめへジャンプ、`/`絞り込み、`x`対象トグル、`X`手動上書き解除。
  `e`はdependencyモード時のみentry指定。
- Resultは完走専用。`Enter`で次のおすすめ、`r`で同じファイルを再挑戦、
  `t`/`Esc`でTreeへ戻る。次がなければ`Enter`はTreeへ戻りリポジトリ完了を示す。
  中断時はResultを挟まない。

Pause（Typingの`Esc`）は再開、最初からやり直し、中断してTreeへ戻るを選ばせる。
ポーズ中も経過時間は進める（要件§3.3）。Searchは入力最優先とし、`j`/`k`を
常に文字入力にする。SettingsとStatsはHomeの子ではなくオーバーレイとし、
Treeからリポジトリを閉じずに開ける。再スキャン不要な設定は閉じた時点で現在の
セッションへ即時反映する。

Prepare画面は置かない（D-016を維持）。`stats`サブコマンドは`S`オーバーレイで
代替するため廃止する。`--last`と走査中の進捗表示は未実装バックログとする。
Splashは場所ではなく起動演出とし、任意キーでスキップする。

フッターは4〜6個、左から「主要アクション → 移動 → 戻る → `?` help」の順に
固定する。動詞は`open` / `start` / `next` / `retry` / `back` / `close` /
`quit`に統一する。現在地を上部に出す。

### 理由

既存のキーは画面ごとに意味が違い、SettingsとStatsがHomeの子であるため
リポジトリ作業中に開けず、ResultのEnterが最も遠いHomeへ飛ぶ。他のTUIや
タイピングアプリと同様に、戻る・終了・確定・検索の意味を固定し、連続写経の
主動線をResultのEnterに置くためです。

### 影響

- D-002 / D-012 / D-016の「完了後は自動で次ファイルを開始せずTreeへ戻る」は、
  自動開始しない点は維持する。完走後の場所はResultとし、Enterで次のおすすめを
  選べるようにする。
- D-014のHome役割（引数なしはHome、Searchはローカルのみ、引数ありはHome省略）
  は維持する。キーマップとSettings/Statsの位置づけ、ResultのEnter先は置き換える。
- プロダクト要件§3.1、§5、§8、§9をこの決定に合わせて更新する。
- 手動上書きは`repo_files.manual_override`（`skip` / `include` / NULL）に保存し、
  既存DBへは起動時の`ALTER TABLE`で列を足す。自動の`skip_reason`は上書きしない。

## D-023: ファイル途中のTypingチェックポイントを保存する

- 状態: 採用（Pause中の経過時間の扱いはD-033で置換）
- 日付: 2026-08-14

### 決定

- TypingまたはPause中は、正規化本文に対する文字カーソル、打鍵数、ミス数、累積経過時間、
  セッション開始時刻、自動インデント設定を`typing_checkpoints`へ最大1秒間隔でupsertする。
- Pause、Treeへの中断、Ctrl-C、完走では即時flushする。Treeやアプリ終了中の時間は経過時間に含めず、
  Pause中は含める。
- 中断ではセッションを確定せず、同じファイルを次に開いたときチェックポイントから同じセッションを再開する。
  「最初からやり直し」だけは未完了セッションを確定し、チェックポイントを削除する。
- Tree、ディレクトリ、リポジトリ、Recentの途中進捗は、カーソルより前で受理済みの改行数から導出する。
  現在入力中の行は数えず、ファイル完走時だけ対象行数全体を完了扱いにする。
- refreshでは同じ相対パスかつ同じ正規化本文ハッシュのチェックポイントだけを維持し、本文変更・削除時は破棄する。

### 理由

ファイル全文を1つの写経単位とする既存モデルを維持しながら、異常終了や中断で入力を失わず、
再開時に速度・正確率の計測も継続するためです。SQLite書き込みを毎打鍵にせず、最大1秒の損失を許容して
入力の遅延を避けます。

### 影響

- `ChunkProgress`は任意の`TypingCheckpoint`を持ち、完了状態とは別に途中行数を集計します。
- 完走トランザクションではセッション確定、ファイル完了、チェックポイント削除を同時に行います。
- 生の打鍵列は保存せず、復元に必要な位置と集計値だけを保存します。

## D-024: ファイル種別ごとの対象トグルをリポジトリ単位で保存する

- 状態: 採用
- 日付: 2026-08-14

### 決定

- 種別キーは「拡張子があれば小文字化した`.ext`、無ければファイル名そのもの」とする
  （`LICENSE`・`Makefile`・`Dockerfile`・`.gitignore`もこの規則でファイル名単位のキーになる）。
- 状態は`Included`/`Excluded`/`Hidden`の3値とする。`Excluded`は対象外理由付きでツリーに
  表示し、`Hidden`は対象外にした上でツリーから完全に取り除く（配下すべてが非表示の
  ディレクトリも非表示にする）。File typesオーバーレイの`Space`/`Enter`はこの順で巡回する。
- 種別ごとのデフォルト値は、拡張子を持たないファイル（`LICENSE`・`Makefile`・`.gitignore`
  等のドットファイルを含む）は`Excluded`固定とし、拡張子を持つファイルはそのリポジトリの
  現在の自動判定（対象なら`Included`、対象外なら`Excluded`）から導出する。
- 設定はSQLiteの`repo_file_types(repository_id, type_key, state)`へリポジトリ単位で保存し、
  `config.toml`は変更しない。
- 優先順位は「手動上書き（`x`/`X`） > 種別トグル > `include_tests`/`include_configs`の自動判定」。
  ただし`include_tests`によるテスト判定はパスベースの別軸であり、種別トグルでは上書きしない。
- 除外（`Excluded`・`Hidden`とも）は新しい`SkipReason::FileTypeDisabled`とし、既存の
  `skip_reason`経路（ツリー表示、進捗集計、`global_summary`のSQL）へそのまま乗せる。
  `Hidden`のツリー非表示は`skip_reason`とは別軸で、`TreeView`が保持する非表示パス集合
  （スキャン結果と保存済み種別設定から都度計算）で実現し、既存の`hide_skipped`設定とは
  独立に効かせる。追加の述語重複は作らない。
- 保存済み設定が空（そのリポジトリで一度も保存していない）のときだけ、リポジトリを開いた直後に
  File typesオーバーレイを自動表示する。閉じるときは変更の有無に関わらず一覧の全種別を明示的に
  保存し、以後は自動表示しない。
- 単一ファイルを直接開く場合は保存済み設定を使わず、常に空の設定（自動判定のみ）を渡す。
- 設定変更は再スキャンで反映する。再スキャンは正規化本文ハッシュで完了状態を引き継ぎ、
  `manual_override`は書き換えない。写経可能なファイルが1つも残らない設定になった場合は
  直前の設定へ戻して元のセッションを維持し、エラーを表示する。
- File typesオーバーレイはTypingの`Esc`（Pause）と同様、Treeを背景に残したまま中央に浮かせる
  ダイアログとして描画する。Settings/Statsのように全画面を上書きする表示にはしない。

### 理由

`LICENSE`のように拡張子を持たないファイルは既存の`CONFIG_NAMES`/`CONFIG_EXTENSIONS`に
入っておらず、常に写経対象になってしまう。逆に`.md`や`.json`は`include_configs`で一括
オン・オフしかできず粒度が粗い。プロジェクトごとにまばらに現れる「写経したくないファイル」を
拾うには、実在するファイル種別を一覧して個別にトグルできる層が要る。対象外理由をツリーに
出したままだと大量のノイズになる種別（バイナリに近いデータファイルや意図的に無視したい
ディレクトリ相当の種別）もあるため、「表示はするが対象外」と「そもそも表示しない」を分けた。
拡張子なしファイルは既定を`Excluded`にすることで、`LICENSE`が写経対象へ紛れ込む問題を
オーバーレイを開かなくても解消する。

### 影響

- `WalkOptions`に`file_types: FileTypePrefs`を追加し、`Copy`ではなく`Clone`にする。
- `TreeView::from_progress_with_order`の上位に`hidden_paths`を渡す
  `TreeView::from_progress_full`を追加する。
- `docs/product-requirements.md`§5.1、§9.2、§9.3を更新する。

## D-025: flowモードはエントリから処理の流れを追う

- 状態: 採用（独立 flow bar は D-026 でヘッダ / 詳細 / Next 行へ畳む）
- 日付: 2026-08-14
- 置換: D-016 の「entry は被参照数が最多」「兄弟は import 出現順」

### 決定

- 進行モード `flow`（設定値 `dependency` は互換エイリアス）は、言語慣習と
  マニフェストから検出したエントリ（`src/main.rs` など）から import を辿る。

- 同階層の兄弟は、本文で束縛名が最初に使われた行の順とする。未使用 import は
  宣言行の順に落ちる。D-016 の「ソース内の import 出現順」は採用しない。
- モードとエントリはリポジトリ単位で SQLite に保存する。未設定リポジトリは
  File types の直後に進め方ダイアログを出す。以後は Tree の `e` で同じ
  ダイアログを開く。`config.progress.mode` は初回ダイアログの既定選択である。
- 専用の Flow ビューは作らず、既存 Tree に flow bar・由来・`▸ next` を重ね、
  Result に next ブロックを出す。ファイル途中で別ファイルへは飛ばない。

### 理由

最も import されているファイルから始めると末端ユーティリティが先頭になり、
リポジトリの処理の流れを追う体験にならないためです。エントリから呼び出し先へ
進み、完走のたびに「次はどこへ流れるか」を見せることで、ファイル単位の写経を
保ったまま流れをなぞれます。

### 影響

- `ImportEdge` に `decl_line` / `first_use_line` / `raw` を持たせる。
- D-016 の結線範囲（Rust / TS / JS / Python、循環打ち切り、未到達は末尾）は維持する。

## D-026: Tree 画面の簡素化

- 状態: 採用（Tree のフッタ件数は D-030 で 6 個へ更新）
- 日付: 2026-08-14
- 更新: D-022 のフッタ件数（Tree のみ 3 個。D-030 で再更新）、D-025 の独立 flow bar

### 決定

- `hide_skipped` の既定を `true` にする。対象外だけのディレクトリはツリーから消える。
- `j`/`k` はディレクトリ行も選択する。対象外ファイルは引き続き飛ばす。`n`/`N` は
  ファイル行だけを辿る。Enter はディレクトリで折りたたみトグル、ファイルで写経開始。
- 開いた直後はすべてのディレクトリを折りたたみ、おすすめファイルの祖先だけを開く。

  （初期の折りたたみは D-030 で全展開に置換。）
- 単一子ディレクトリのチェーンは 1 行に圧縮する。圧縮行の `path` は深い側。幅が足りない
  ときは中間を `…` で省略する。
- 行末の `[n/m]` は廃し、選択行の詳細行へ集約する。ディレクトリ行は右寄せ 8 セルの

- ヘッダのゲージ比率は §7 どおり行数ベースのまま。ラベルだけファイル数

  （フッタ件数と折りたたみキーの再掲は D-030 が優先する。）

Tree に状態・理由・行数・おすすめ・flow bar・長いフッタが同時に乗り、次に打つ
ファイルへ到達するまでの認知負荷が高すぎるためです。対象だけを折りたたんで見せ、
次の 1 ファイルをヘッダに固定し、数値と補助キーを詳細・Help へ退けることで、

## D-028: 対象外の表示はTreeの`.`でセッション限りに切り替える

- 状態: 採用
- 日付: 2026-08-15
- 置換: D-026 の「`j`/`k`は対象外ファイルを飛ばす」

### 決定

Tree に `.` を追加し、対象外ファイルの表示/非表示をセッション限りで切り替える。
`progress.hide_skipped` は Tree を開いた時点の初期値としてのみ使い、`.` では
書き換えない。永続的に既定を変えたい場合は従来どおり Settings（`,`）で行う。

対象外を表示している間は `j`/`k` が対象外行にも止まる。対象外ファイルを個別に
写経対象へ戻す手順は「`.`で表示 → カーソルを当てて `x`」に一本化する。

トグルしてもカーソルは同じ行に留める。選択中の行が消える場合（対象外行を選んだ
まま隠した場合など）は、元の並びで直上の残っている行へ寄せる。これはツリー再構築
全般に効かせ、フィルタや折りたたみでも同じ規則でカーソルを復元する。

スクロール位置（先頭に描画する行）は`TreeView`が持ち、リストウィジェットに委ねない。
ウィジェット任せだと毎フレーム offset 0 から選択行が見える最小量だけスクロールする
ため、行数が大きく変わるトグルのたびにカーソルが画面下端へ飛んでいた。再構築時は
カーソルの画面上の行位置を保つよう offset を求め直し、レイアウトシフトを避ける。

ただし開いた直後はスクロールを先頭に置く。リスト高さは最初の描画まで分からないため、
高さが確定した時点で選択行が見える分だけ送る。選択行を最上段に貼り付けると、
ツリーのどこを開いているのか読めずかえって混乱する。

スクロール量は `rows.len() - 高さ` で頭打ちにしない。頭打ちにすると、非表示時に
一画面へ収まっていたツリーでは対象外を出しても送れず、上に挿入された分だけ
選択行が下へ押し出されてしまう。末尾に空行が残る方を許容する。

折りたたみ状態は「閉じているディレクトリ」ではなく「開いたディレクトリ」で持つ。
閉じている側を持つと、対象外を表示して初めて現れるディレクトリが集合に載らず、
展開状態で出てきてしまう。開いた側を持てば、未知のディレクトリは自動的に閉じた
扱いになり、対象外を `.` で出したときに中身が一度に広がらない。開いた直後の
全展開（D-030）とは独立で、あとから現れたディレクトリにだけ効く。

詳細行右端の件数は `hide_skipped` の値に依存せず常に出し、非表示なら
`N excluded · .`、表示中なら `N excluded shown · .` と表記する。

### 理由

切り替えが Settings にしかなく、しかも切り替えると config に永続保存されるため、
一度 `hide_skipped = false` にすると次回以降ずっと対象外が並び、既定値が `true`
であるにもかかわらず「非表示が効いていない」ように見える事故が起きた。
Tree を見ながら一時的に確認する操作と、既定を変える操作は分けるべきだった。

また、対象外を表示してもカーソルが当たらないと `x` で復帰させられず、表示できる
意味が薄かった。非表示モードでは対象外行がそもそも行として存在しないため、
スキップ処理を外しても既定の操作感は D-026 から変わらない。

### 影響

- `TreeView::toggle_hide_skipped` を追加し、`move_by` からスキップ処理を外す。
- `excluded_count` から `hide_skipped` 依存を外す。
- `refresh_rows` のカーソル復元を、消えた行のインデックスをクランプする方式から
  元の並びをたどって生存行を探す方式（`surviving_row`）に変える。
- `TreeView`に`offset`を持たせ、選択を変える経路は`select_index`経由に揃える。
  `draw_tree`は`ListState::with_offset`でこの値を渡す。
- `TreeView::collapsed`を`opened`に反転する。`apply_collapse`の述語も反転する。
- Settings を開いて閉じると `apply_live_settings` が config 値で上書きするため、
  `.` の切り替え結果は失われる。初期値を持つのは config 側という整理に従う。
- `docs/product-requirements.md` §9.2 と §11 を更新する。

## D-030: Tree の全展開トグルとフッタ拡充

- 状態: 採用
- 日付: 2026-08-15
- 置換: D-026 の「Tree のフッタは 3 項目」、D-026 の「開いた直後は折りたたむ」

### 決定

- Tree を開いた直後はすべてのディレクトリを展開する。カーソルはおすすめファイルへ置く。
- Tree の `o` ですべてのディレクトリを展開／たたむ。すでにすべて開いているときは、
  選択中の行の祖先以外を折りたたみ、カーソルは同じ行に留める。
- 個別の開閉は従来どおり `l`/`→`/`Space` で展開、`h`/`←` で折りたたみ、
  ディレクトリ上の `Enter` でトグルする。
- Tree のフッタは 6 項目とする。日本語既定は `Enter 開く` · `j/k 移動` ·
  `h/l 開閉` · `o たたむ` · `Tab おすすめ` · `? 詳細`。たたんだあとは
  `o 全展開`。フィルタ中は `Esc 解除` · `n/N 次へ` · `j/k 移動` · `Enter 開く` ·
  `? 詳細`。
- `e` / `t` / `x` / `X` / `g` / `G` / `Ctrl-d` / `Ctrl-u` / `/` / `.` は Help に残す。
  `.` は詳細行右端の件数にも出す。`h`/`l`/`o`/`Tab` はフッタと Help の両方に出す。

### 理由

フォルダの開閉がフッタから見えず、ディレクトリを一つずつ開く手数も多い。
全展開の切り替えと、折りたたみ・おすすめをフッタへ戻すことで、Tree 上での探索を
短くする。件数は D-022 の 4〜6 個の範囲に戻す。

### 影響

- `docs/product-requirements.md` §9.2、§9.3、§9.4 を更新する。
- D-026 の「Tree のフッタは 3 項目」と、追加キーをフッタに出さない方針、
  および「開いた直後は折りたたむ」は、この決定が優先する。
  対象外を `.` で出したときに初めて現れるディレクトリは、D-028 どおり閉じたまま出す。

## D-031: 要素区切りはTUI慣習に合わせ、themeヘルパーを正とする

## D-033: Typing の Esc は必ず外側へ進み、Pause は計測を止める

- 状態: 採用
- 日付: 2026-08-15
- 置換: D-022 の「Pause は `t` で中断して Tree へ戻る」「Result は `t`/`Esc` で Tree へ戻る」、
  D-023 の「Pause 中は経過時間に含める」
- 更新: D-022（オーバーレイの `Esc` は必ず同じ場所へ戻る、の Pause 例外）、
  D-029（動詞に「最初から」/ `restart` を追加）、
  D-030（フッタ 4〜6 個の下限は Typing のヒント帯へ適用しない）

### 決定

- Pause の `Esc` / `q` は Typing へ戻らず、中断して Tree へ抜ける。`Enter` / `Space` で再開し、
  `r` で最初からやり直す。`t` は廃止する。Esc は全画面で「1 つ外へ」に統一し、
  Typing → Pause → Tree → Home → 終了 と連打だけで外に出られる状態にする。
- Pause 中は経過時間を止める。Typing を離れている時間と同じ扱いとし、再開時に
  計測の起点を再開時刻へずらす。Pause 中の強制保存は止まった経過時間を保存する。
- Result の `t` を廃止する。「戻る」はどの場所でも `Esc` / `q` に統一し、
  `t` は Tree の File types だけを意味する。Result の `t` は無反応とする。
- Typing のキーヒントはフッタ行を足さず、ステータス行の右端へ `theme::key_hints` で
  右寄せする。左のデータ欄は `theme::field_sep()` のままとし、2 系統を連結しない。
  幅が足りないときはヒントから順に落とし、データ欄は削らない。
- Tree へ戻るとき、カーソルは直前に打っていたファイルへ置く。祖先ディレクトリが
  閉じていれば開いてから合わせる。絞り込みで対象が消えている場合は動かさない。
- チェックポイントを持つファイルはツリーで `◐` を付け、Next 行を「Enter で続きから」
  に変える。Help 凡例へ `◐ 入力途中` を足す。
- 「最初からやり直し」の動詞を「最初から」/ `restart` とし、完走したファイルを
  もう一度開く「再挑戦」/ `retry` と区別する。

### 理由

- `Esc` は他のすべての場所で「1 つ戻る」を意味するのに、Typing だけはダイアログを開き、
  そのダイアログの `Esc` が元の位置へ戻していた。最も強い「抜けたい」反射が何も起こさない
  ループになり、実際の出口は 3 番目に置かれた `t` だった。`t` は Tree では「ファイル種別」を
  意味する別の語で、日本語既定の UI では「ツリー」を想起させる手がかりもない。
- Typing を離れると計測は止まりチェックポイントは残るのに、Pause 中だけ時計が進んでいた。
  つまり「ポーズ」は Tree へ戻るより厳密に不利で、カード本文は黄色でその不利を警告していた。
  名前が実態を偽っている状態なので、名前ではなく実装の側を直す。計測の起点をずらす手当ては
  `from_checkpoint` が Typing 外の時間を除くのに使っている計算と同じで、新しい概念を足さない。
- ステータス行がデータ区切り `│` のあとにキーヒントを続けており、D-031 と
  `docs/ui-guidelines.md` §2 の 2 系統の使い分けに反していた。ヒント帯を右端へ分けることで、
  行を増やさずに区切りの体系を戻す。
- 中断が非破壊であることは、戻った先のカーソルとツリーの見た目でしか伝わらない。
  `◐` と「続きから」を出し、カーソルを打っていたファイルへ置くことで、再開が 1 打で済むと
  分かるようにする。

### 影響

- `TypingEngine::resume_at` を足す。メインループの `Tick` と定期 `autosave_checkpoint` は
  Pause 中スキップし、`autosave_checkpoint` 内の `Tick` も Pause 中は打たない。
- `TreeRow` に `in_progress`、`TreeView` に `recommend_resume` を足す。判定は
  `ChunkProgress::checkpoint` の有無で行う。受理済み行数は 0 のままでも「入力途中」に
  なりうるため、行数から導出しない。
- `TreeView::reveal_path` を足す。祖先を開く → `refresh_rows` → `jump_to_path` の順で呼ぶ。
  `interrupt_typing` は `refresh_rows` の代わりにこれを呼ぶ。
- `UiStrings` に `restart` / `enter_to_resume` / `legend_in_progress` を足し、
  `typing_esc_pause` と `tree` を削る。`pause_timer` / `pause_idle` は停止の文言へ差し替える。
- Help 凡例が 1 行増えるため、Home と Tree の Help カード高さを 1 行ずつ広げる。
- `docs/product-requirements.md` §3.1、§3.3、§7、§9.1、§9.2、§9.3、§9.4 を更新する。
- `docs/ui-guidelines.md` §2 に Typing のステータス行の扱いを足す。
- `docs/architecture.md` の計測と「中断と再開」、`docs/implementation-plan.md` の
  受け入れ条件 3 と 8、`README.md` の操作の目安を更新する。
- D-023 のチェックポイント方針そのもの（保存項目、1 秒間隔、refresh 時のハッシュ照合）は
  変えない。Pause 中の経過時間の扱いだけを置き換える。

## D-034: 配布はGitHub Releasesとinstall.shで行い、mainの直コミット運用は維持する

- 状態: 採用
- 日付: 2026-08-15

### 決定

知り合いに使ってもらうための配布導線を、次の構成に決めます。

- ビルド済みバイナリをGitHub Releasesへ置き、`install.sh`を
  `curl -fsSL ... | sh`で実行してもらう。crates.io、npm、Homebrew tapへは
  公開しない。
- ビルド対象はmacOS `aarch64-apple-darwin`、Linux `x86_64-unknown-linux-gnu`、
  Windows `x86_64-pc-windows-msvc`の3つ。Windowsはバイナリを出すだけで
  動作を保証しない。
- Linuxのビルドは`ubuntu-latest`ではなく`ubuntu-22.04`で行う。
- `install.sh`はGitHub APIを叩かず、`releases/latest/download/`の
  リダイレクトだけを使う。ダウンロードした資材は`SHA256SUMS`と照合し、
  一致しなければ中止する。
- `main`への直コミット運用は変えず、branch protectionもrulesetもかけない。
  CIは通知装置として置き、品質ゲートは`release.yml`の`verify`ジョブに置く。
  `verify`はタグ名と`Cargo.toml`の`version`の一致も検査する。
- `CHANGELOG.md`は持たず、リリースノートは`gh release --generate-notes`に
  委ねる。バージョンはSemVerとし、0.xの間は破壊的変更でminorを上げる。
- 依存クレートのライセンス表示は`cargo about`で`THIRD-PARTY-LICENSES.md`を
  生成し、リポジトリと配布アーカイブの両方に置く。再生成は手作業とする。
- コード署名と公証は行わない。

### 理由

- 現状インストール手段がなく、READMEの例がすべて`cargo run`だった。
  `rusqlite`のbundled SQLiteとtree-sitterのgrammarがCコンパイラを要求するため、
  ソースからのビルドを前提にすると、Rustを持たない知り合いには渡せない。
- パッケージマネージャ配布は、名前の確保、公開の取り消しにくさ、tapの保守が
  増える。「知り合いが試せる」ために必要な範囲を超えるため、今回は採らない。
- branch protectionを入れると`main`直pushが全面的に止まり、AGENTS.mdの
  Git運用ルールと正面衝突する。一方で他人が使うバイナリを配る以上、壊れたコードが
  そのまま配布物になる経路は塞ぐ必要がある。両立させるため、ゲートを
  「mainへのpush」ではなく「外へ出るタグ」の側へ置いた。途中経過が赤くても
  作業は止まらず、赤いままリリースは出ない。
- `ubuntu-latest`（glibc 2.39）でビルドすると、少し古いディストリビューションで
  動かないバイナリになる。配る相手の環境を選ばないほうがよいため、
  意図的に古いランナーを固定する。
- GitHub APIを使わない方針は本体の実装ルールにもあり、レート制限を避けられる。
  導線側も同じ流儀に揃えておくと、説明が一貫する。
- `repomonk --version`は`CARGO_PKG_VERSION`由来のため、タグと`Cargo.toml`が
  ズレると配布物が自分のバージョンについて嘘をつく。人手の注意ではなく
  ワークフローで落とす。
- 依存195クレートのライセンスを確認したところ、GPL、AGPL、CDDL、EPLは0件で、
  `MIT OR Apache-2.0`が大半だった。`option-ext`のMPL-2.0はファイル単位の
  copyleftで、改変せずリンクする使い方では自分のコードの開示義務が生じない。
  バイナリ配布に支障はないが、表示義務は残るため同梱する。

### 影響

- `.github/workflows/ci.yml`と`.github/workflows/release.yml`を新規に追加する。
  `.github/`ディレクトリ自体がこれまで存在しなかった。
- `install.sh`を新規に追加する。`REPOMONK_VERSION`と`REPOMONK_INSTALL_DIR`で
  バージョンと配置先を差し替えられるようにする。
- `about.toml`、`about.hbs`、`THIRD-PARTY-LICENSES.md`を追加する。
- `SECURITY.md`を追加する。外部送信がないという前提のもとで、想定するリスクを
  `git`の引数組み立て、シンボリックリンク、`--purge`の削除対象検証に絞って書く。
  GitHubのPrivate vulnerability reportingの有効化はリポジトリ設定側の作業になる。
- `AGENTS.md`に「リリース運用ルール」を新設する。既存の「Git運用ルール」は
  変更しない。エージェントはユーザーの明示指示なしにタグをpushしない。
- `README.md`にインストール節、対応環境、データの保存先、アンインストール手順を
  足し、使い方の例を`cargo run --`から`repomonk`へ書き換える。`cargo run`の例は
  開発節へ移す。
- `docs/development.md`に§8「配布とリリース」を足す。リリース手順を自動化しない
  ぶん、この手順書が正になる。
- `docs/public-release-checklist.md`の「実装開始後に必須」のうち、CI追加、
  依存ライセンス確認、リリースバイナリの明記、READMEの記載、`SECURITY.md`の
  5項目を対応済みにする。
- 実装コードは変更しない。
