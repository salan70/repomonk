# プロダクト要件

状態: MVP実装済み（2026-08-11）。画面遷移とキーマップはD-022で再定義済み。

原典: 2026-08-11に提示された「repomonk 仕様書（TUI 写経アプリ）」

この文書は、原典の仕様を実装とテストに使える形へ整理したものです。
ユーザーから見える挙動について、この文書を正とします。未決事項は実装で暗黙に
決めず、末尾に分離して記録します。

## 1. 目的と非目標

`repomonk` は、実在するGitHubリポジトリのソースコードを写経し、完了状況を
ファイルツリーで可視化するRust製TUIです。

達成すること:

- GitHubリポジトリまたはローカルパスから、ワンコマンドで写経を開始できる。
- 速度ではなく、打ちながらコードを体に入れる体験を中心にする。
- ファイルとディレクトリの進捗により、リポジトリを塗りつぶす感覚を作る。
- 速度はローカルで計測するが、常時の主要表示にはしない。
- Typing画面の本文を、エディタのような字句レベルの構文色で表示する。

対象外とすること:

- 解説、LSP、定義ジャンプ、補完、ホバー、診断、リネームなどの読解支援や
  エディタ機能。構文色のために言語サーバーを起動することも含む。
- タイムアタック、ランキングなど速度を競う機能
- 効果音、BGM、マルチプレイ、Web版
- GitHub APIを利用したリポジトリ検索
- 全ターミナルでの動作保証

打鍵イベントと集計結果は外部送信しません。`--purge`により、`repomonk`が
管理するリポジトリキャッシュ、進捗、セッション、統計をすべて削除できることを
必須要件とします。

## 2. 用語

- **ファイル本文**: 写経の最小単位。対象ファイルを正規化した全文。
- **セッション**: ファイルを打ち始めてから完走または「最初からやり直し」を選ぶまでの期間。
  Treeへの中断やアプリ終了ではセッションを確定せず、保存したチェックポイントから続ける。
- **進行モード**: 次に打つファイルを決める戦略。進捗自体はモードに依存しない。
- **場所（Place）**: Home、Tree、Typing、Result。縦1本の階層。Escで1つ戻る。
- **オーバーレイ（Overlay）**: Help、Search、Settings、Stats、Pause。場所の上に
  開き、閉じると必ず元の場所へ戻る。

## 3. 打鍵

### 3.1 入力判定

- 次に期待される文字と一致した入力だけを受理する。
- 誤入力は本文へ反映せず、カーソルも進めない。
- 誤入力時は期待される文字を150ms赤く表示し、ミス数を1増やす。
- Backspaceを許可する。Backspaceを使っても累積ミス数は減らさない。
- 保持された改行はEnterで入力させる。
- 時間制限とアイドル除外は設けない。
- Escでポーズオーバーレイを開く。再開、最初からやり直し、中断してTreeへ戻る
  を選べる。中断時はファイルを完了扱いにしない。

### 3.2 正規化と自動入力

- タブを半角スペースへ変換する。既定幅は4とする。
- 写経前に行末の余分な空白を除去する。
- 非ASCII文字を含む行は、正規化時に除外する。
- 行頭インデントは自動挿入し、打鍵数に含めない。
- 括弧の自動補完は無効とする。設定キーは用意するが、MVPでは実装しない。

### 3.3 計測

- リアルタイムKPMは既定で表示しない。
- 結果にはKPM、WPM、正確率、前回比、ミス文字上位5件を表示できる。
- 自動挿入した文字は打鍵数や速度の計算から除外する。
- 手を止めた時間も経過時間に含める。
- TypingまたはPause中は入力位置と計測値を最大1秒間隔で保存する。Pause、Treeへの中断、
  Ctrl-C、完走では即時保存する。Typingを離れている時間は経過時間に含めない。

## 4. 題材の取得

入力として次を受け付けます。

- `repomonk https://github.com/<owner>/<repo>`
- `repomonk <ローカルパス>`
- ホームの検索モーダルにおける`owner/repo`

リモートリポジトリは、システムの`git`を使ってshallow cloneし、blob filterを
有効にします。認証は既存のcredential helperまたはSSH鍵に委ねます。
キャッシュ先は`~/.cache/repomonk/repos/<owner>__<repo>/`とし、`--refresh`が
ない限り再利用します。

GitHub検索APIは使いません。GitHub URLまたは`owner/repo`以外の文字列は、
ローカルの履歴とキャッシュだけを対象にしたあいまい検索として扱います。

## 5. ファイルの対象判定

ファイルの実効状態は次の3種類です。

- `todo`: 写経対象で未完了。
- `done`: ファイル本文を完走済み。
- `skipped`: 対象外。進捗の分母からも外す。

次のファイルは自動で対象外にします。

- VCS、依存物、生成物、ビルド成果物として既知のディレクトリ配下
- ロックファイルおよび既知の生成ファイルパターン
- バイナリファイル
- 200文字を超える行を含むファイル
- 5,000行を超えるファイル
- `include_tests`が無効な場合のテストファイル
- `include_configs`が無効な場合の設定・ドキュメント・データ記述ファイル
  （`.toml`、`.md`、`.yaml`、`.json`など。HTML / CSSは含まない）
- 正規化後に写経可能な行を1行も残せないファイル

対象外にした理由は保存し、ツリーに表示します。Treeの`x`は選択中のファイル、
またはディレクトリ配下の写経対象をトグルします。`X`は手動上書きを解除し、
自動判定へ戻します。手動上書きは自動判定より常に優先し、refresh後も維持します。

## 6. 抽出

### 6.1 ファイル本文の生成

- 対象ファイルごとに正規化済み全文を1つの写経単位として生成する。
- 空行境界や行数上限による分割は行わない。
- ラベルによる行の除外後に行数を判定する。除外行は進捗の分母にも入れない。
- 正規化後の行数が0なら、そのファイルは対象外とする。

### 6.2 行ラベル

tree-sitterはファイルを分割するためではなく、行を次の種別へ分類するために
使います。

- `import`: import、use、require、includeの宣言
- `doc`: ドキュメントコメントやdocstring
- `comment`: その他のコメント
- `code`: 上記以外

既定ではimportを除外、docを採用、通常コメントを除外します。対応パーサがない
言語は正規表現へフォールバックします。

Tier 1はRust、TypeScript、TSX、JavaScript、Python、Go、Java、C、C++、C#、
Ruby、PHP、Kotlin、Swift、Dart、Bashです。パーサはCargo featureで切り替え、
既定ではすべて有効にします。Dartは対応を確定する前に、パーサのビルド可否と
import・コメントノードの利用可否を検証します。

## 7. 進捗とrefresh

- ファイル完了は、そのファイル本文を完走したかどうかで決める。
- 完了率は「完了または途中入力済みの正規化済み行数合計 / 対象ファイルの正規化済み行数合計」
  とする。途中入力中の現在行は、改行を受理するまで数えない。
- 中断したファイルは保存済みチェックポイントから再開する。カーソル、打鍵数、ミス数、
  累積経過時間を同じセッションとして引き継ぐ。
- Pauseの「最初からやり直し」はチェックポイントを破棄し、未完了セッションを確定して先頭から始める。
- 全ファイルが`done`または`skipped`なら、リポジトリ完了とする。
- 初回スキャンではファイル、正規化本文、依存関係を並列生成する。走査中の
  進捗表示はバックログとする（Prepare画面は置かない。D-016 / D-022）。
- refresh時は、ファイル全体の正規化済み本文のSHA-256で照合する。行番号は使わない。
- 一致するファイル本文は完了を維持する。
- 変更されたファイル本文は完了を解除し、変更マークを表示する。
- 消えたファイルは履歴として残すが、集計から除外する。

## 8. 進行モード

### 8.1 manual

既定のモードです。ユーザーがツリーからファイルを選びます。おすすめはパス順の
未完了ファイル先頭です。

ファイルを選ぶと、チャンク一覧を出さず直接Typingへ入ります。ファイルを完了したら
自動で別ファイルへ移動せず、Resultを表示します。ResultのEnterで次のおすすめを
開始でき、Esc/`t`でTreeへ戻ります。

### 8.2 dependency

検出または手動選択したエントリポイントから、リポジトリ内部のimportを辿ります。
将来の初期実装対象はRust、TypeScript / JavaScript、Pythonとし、未対応言語は
manualへフォールバックします。

- 既定はtop-down DFSとする。
- 兄弟はソース内のimport出現順とする。
- bottom-upを設定可能にする。
- 循環は訪問済みファイルで打ち切る。
- 到達不能な対象ファイルを末尾へパス順で追加する。
- 順番は保存せず、依存関係から毎回計算する。

候補が複数なら最も多くimportされるファイルを既定の起点とします。ツリーの`e`で
明示的な起点を指定できます。Prepare画面は置かない（D-016）。

## 9. 画面と遷移

画面は場所とオーバーレイの2層で構成します（D-022）。

- **場所**: Home → Tree → Typing → Result。縦1本の階層。
- **オーバーレイ**: Help、Search、Settings、Stats、Pause。どの場所からでも開き、
  閉じると必ず元の場所へ戻る。場所は変わらない。

Splashは場所ではなく、引数あり起動時の演出です。任意キーでスキップし、`q`や
`Esc`でも終了せずスキップに倒します。Prepare画面は置きません。走査中の進捗
表示はバックログです。`--last`は未実装のバックログです。`stats`サブコマンドは
置かず、`S`オーバーレイで代替します。

リポジトリ引数を渡した場合はHomeを省略し、Splash（任意）のあとTreeを開きます。

### 9.1 共通キー（Typing中を除く）

- `Esc`: オーバーレイがあれば閉じる。無ければ1つ戻る。Homeでは何もしない。
- `q`: `Esc`と同義。Homeでのみ終了する。「`q`を押し続ければ必ず出られる」。
- `Ctrl-C`: どこでも即終了。Typing中は現在のチェックポイントを保存してから終了する。
- `?`: Helpを開く。
- `,`: Settingsを開く。
- `S`: Statsを開く。
- `/`: 検索。Homeではリポジトリ検索、Treeではファイル絞り込み。

Homeの`s`（検索）と`c`（設定）はエイリアスとして残します。Homeの`g`はStats
ではなく、リスト先頭への移動です。

### 9.2 場所

**Home**

- `j`/`k`、`↑`/`↓`でRecentを選択する。`g`/`G`で先頭/末尾へ移動する。
- `Enter`で選択中のリポジトリを開く。
- `/`でSearchを開く。`q`で終了する。

**Tree**

ファイル状態、対象外理由、行数進捗、変更状態、ディレクトリ進捗、おすすめ、
dependency時の順番号を表示します。ツリーは表示行の一次元ベクタへ展開し、
可視範囲だけを描画します。ディレクトリとファイルの進捗は
`[進捗行数/対象行数 lines]`の形式で示します。途中ファイルは受理済み改行までを進捗行数とし、
完走したファイルだけが`done`になります。

- `j`/`k`、`↑`/`↓`で有効なファイル間を移動する。ディレクトリと対象外ファイルは
  飛ばす。`g`/`G`で先頭/末尾、`Ctrl-d`/`Ctrl-u`で半画面スクロールする。
- `l`/`→`/`Space`で展開、`h`/`←`で折りたたむ。閉じている場合は親へ移動する。
- `Enter`でファイルを開く。ディレクトリでは展開をトグルする。
- `Tab`でおすすめへジャンプする。
- `/`で絞り込み、`n`/`N`で前後の一致へ移動し、`Esc`で解除する。
- `x`で写経対象をトグルする。ディレクトリなら配下を一括トグルする。
- `X`で手動上書きを解除し、自動判定へ戻す。
- `e`はdependencyモード時のみ、選択中の写経対象ファイルをentryに指定する。

**Typing**

現在行を中央に固定し、対象位置と行進捗（現在行 / 総行）を表示します。本文は
ファイル拡張子に応じた字句レベルの構文色で表示します。打鍵済みと未入力は同じ
構文色を保ったまま明るさで区別し、カーソル、ミスフラッシュ、演出は構文色より
優先します。対応する構文がない場合も単色で表示して打鍵を継続できるものとします。

文字、`Enter`、`Backspace`は本文入力だけに使います。制御は`Esc`（ポーズ）と
`Ctrl-C`だけです。

**Result**

完走時だけ表示します。達成を主、速度と正確率を従とします。中断時はResultを
挟まずTreeへ戻ります。

- `Enter`で次のおすすめを開始する。次がなければTreeへ戻り、リポジトリ完了を
  表示する。
- `r`で同じファイルをもう一度開始する。
- `t`/`Esc`でTreeへ戻る。

### 9.3 オーバーレイ

**Pause**（Typingの`Esc`）

- `Esc`/`Enter`で再開する。
- `r`で最初からやり直す。
- `t`で中断してTreeへ戻る。中断時はResultを挟まない。
- ポーズ中も経過時間は進む（§3.3）。その旨を画面に示す。

**Search**

入力を最優先します。移動は`↑`/`↓`と`Ctrl-n`/`Ctrl-p`だけです。`j`/`k`は常に
文字入力です。

**Settings**

- `j`/`k`で移動、`h`/`l`で値変更、`Enter`/`Space`でトグルする。
- `Esc`/`q`で閉じ、元の場所へ戻る。
- 再スキャン不要な項目（`fx.*`、`typing.show_live_speed`、
  `typing.syntax_highlight`、`progress.hide_skipped`）は閉じた時点で現在の
  セッションへ即時反映する。
- 再スキャンが必要な項目は行ごとに「次回オープンから」と表示する。

**Stats**

- `j`/`k`、`g`/`G`でスクロールする。
- `Esc`/`q`で閉じ、元の場所へ戻る。

**Help**

現在の場所のキー、共通キー、記号凡例を表示します。凡例は`✓ done`、`○ todo`、
`· skipped`、`[done/total lines]`、`▸ recommend`、dependency順の番号です。

### 9.4 表示

- フッターは4〜6個までとする。左から「主要アクション → 移動 → 戻る → `?` help」
  の順で固定し、`?`は全画面に置く。
- 動詞は`open`、`start`、`next`、`retry`、`back`、`close`、`quit`に統一する。
- 現在地を上部に出す。Treeは`owner/repo`、TypingとResultは
  `owner/repo › src/main.rs`とする。

## 10. 演出

演出はカーソル周辺だけに置き、入力処理を遅延させてはいけません。

- カーソルのグローと100〜150msの残光
- 改行時のイナズマ状軌跡と3段階のノーミス強化
- ミス時の連続記録リセット
- ミス時は赤フラッシュのみとし、画面シェイクは行わない
- 入力と描画を分離し、16msティックと差分描画を使う

演出は無効化可能とし、コア機能の正しさには影響させません。

演出プリセットは次の5種類を提供します。`classic`、`blaze`、`smear`、
`ripple`は正解打鍵でカーソルが前進したタイミングにだけ発火し、本文セル上で
完結します。`fireworks`もカーソル移動時の演出は本文セル上で完結し、
追加の重力演出だけがカーソル周辺で停止中にも段階的に変化します。

- `classic`: 残光、改行トレイル、ノーミス強化を使う標準演出
- `blaze`: 前カーソルから現カーソルへ黄〜オレンジの軌跡を引き、本体を強く発光させる演出
- `smear`: 直近数回のカーソル位置を長いシアン軌跡として残す演出
- `ripple`: カーソル位置から広がる同心円状の色波紋
- `fireworks`: 紫白のブレイズ軌跡、放射火花、縦斬り、分岐する稲妻をカーソル移動時に重ね、
  停止中はカーソル周辺の重力井戸・落下粒子・脈動コア・重力波を段階的に表示する演出

`flare`/`ember`は`blaze`、`comet`/`matrix`は`smear`、`pulse`は`ripple`
として設定読み込み時に互換解釈します。

## 11. 設定

設定ファイルは`~/.config/repomonk/config.toml`です。

```toml
[content]
include_imports = false
include_doc_comments = true
include_comments = false
include_tests = false
include_configs = false
tab_width = 4

[typing]
auto_indent = true
auto_close_brackets = false
allow_backspace = true
syntax_highlight = true
show_live_speed = false

[progress]
mode = "manual"
dependency_direction = "top_down"
keep_done_on_refresh = true
hide_skipped = false

[fx]
enabled = true
intensity = "normal"
preset = "classic"
```

`typing.syntax_highlight` はTyping画面の構文色を切り替えます。既定値は`true`で、
無効にしても打鍵判定、進捗、演出には影響しません。

不正な設定値は無視せず、修正方法が分かるエラーを表示します。

## 12. プライバシーと削除

- アナリティクスやテレメトリを実装しない。
- 生の打鍵イベントと集計結果を端末外へ送信しない。
- `--purge`は、明示的な確認後にアプリ管理下のキャッシュと永続データだけを削除する。
- purgeでは、アプリ管理ディレクトリ外へ向くシンボリックリンクを辿らない。

## 13. 未決事項

依存する機能へ着手する前に、次を明示的に決定します。

- 完了ファイルのリセット粒度と複数周の履歴
- 大規模リポジトリにおける一括抽出と遅延抽出の境界
- 言語別依存解決で許容する取りこぼし
- ブランチやコミットをまたぐリポジトリ同一性
- キャッシュ上限と退避・削除方針
- SQLiteの最終スキーマ
- Backspaceが自動挿入インデントを越えられるか
- KPM、WPM、正確率の厳密な計算式

明記されたものを除き、これらはMVPの着手を妨げません。
