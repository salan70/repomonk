# MVP実装計画

## 1. ゴール

細かなv0.xリリースは設けません。AIエージェントで領域を分担し、次の縦方向の
体験が一通り動く状態を、単一のMVPとして完成させます。

```text
URL / ローカルrepo
  → cloneまたは走査
  → 進捗付きファイルツリー
  → ファイル単位写経
  → リザルト
  → ツリー更新
  → 再起動後も完了・途中位置を維持
```

## 2. MVPに含めるもの

- `repomonk`（引数なし）でのHome起動、および
  `repomonk <GitHub URL | ローカルパス>`からの直接起動（Home省略）
- HomeのRecent / Summary、Searchモーダル（ローカル候補のみ）、達成サマリ（`S`）
- system `git`によるshallow cloneとキャッシュ再利用
- リポジトリ走査、自動対象外判定、対象外理由
- 共通規則による正規化とファイル全文の写経単位抽出
- manualモードのファイルツリー（チャンク一覧なし。Enterで直接Typing）
- 強制修正、自動インデント、Enter、Backspace、Escポーズ／中断を備えた打鍵エンジン
- 完了進捗、経過時間、ミス数、正確率、KPMを表示するリザルト
- SQLiteによるファイル完了とセッションのローカル保存
- Typing中のチェックポイント自動保存と、カーソル・計測値の途中再開
- 正規化済みファイル本文ハッシュによる再走査時の完了引き継ぎ
- 行数ベースのファイル・ディレクトリ進捗表示
- 確認付き`--purge`
- エラー表示と、終了経路を問わない端末復元

ローカルパスはファイルとディレクトリの両方を受け付けます。単一ファイルの場合も
内部では1ファイルのリポジトリとして扱います。

## 3. MVPに含めないもの

- Prepare進捗画面、`--last`、`stats`サブコマンド（`stats`は`S`オーバーレイで代替。D-022）
- tree-sitterと言語別行ラベル、import・コメントの設定フィルタ（→ 実装済み。D-016）
- dependency / directoryモードと依存グラフ（dependencyのみ実装済み。D-016）
- ソート切り替え
- 変更マーク、消えたファイル履歴などrefreshの詳細UI
- フル統計画面（草、速度ヒートマップ、2-gram、詳細なミス分析）
- 設定ファイルによるカスタマイズ（→ 実装済み。D-015）
- 並列スキャンの最適化
- 描画スレッド分離
- 周回履歴の保持（完了済みを再度開くこと、およびResultの`r`再挑戦はD-022の対象）

MVP外の項目は削除ではなく、MVP後のバックログです。
（Home / Search / 達成サマリ、および演出・Splashはユーザー指示により実装済み。）

## 4. AIエージェントの担当

4並列枠を前提とし、親エージェントを統合担当、3つのサブエージェントを実装担当に
します。実際の担当数は作業時の依存関係に応じて減らして構いません。

### 統合担当

- Cargoプロジェクト、共有型、公開trait、`main.rs`、`lib.rs`
- `Cargo.toml`、`Cargo.lock`、DBマイグレーション
- Appの画面遷移と全モジュールの結線
- E2Eテスト、最終品質ゲート、文書更新

### 打鍵・抽出担当

- `domain/typing.rs`と打鍵状態遷移テスト
- `domain/content.rs`、`scan/extract.rs`と正規化・ファイル本文抽出テスト
- UI、SQLite、実ファイルI/Oには依存しない

### 取得・永続化担当

- `source/`、`scan/walk.rs`、`store/`
- clone、キャッシュ、対象外判定、SQLite、ハッシュ照合
- fixtureを使った統合テスト

### TUI担当

- `ui/`のTree、Typing、Result
- 端末イベント変換と端末状態の復元
- ドメイン判断やDB処理を重複実装しない

## 5. 統合作業の流れ

これはリリース段階ではなく、1回のMVP開発内での統合順です。

1. 統合担当が共有型、trait、エラー境界、fixture、テスト骨格を確定する。
2. 3担当が所有ファイルを分けて並列実装し、それぞれ単体テストを通す。
3. 統合担当が走査からResultまでのheadlessなアプリフローを結線する。
4. TUIを接続し、fixtureリポジトリでE2Eシナリオを通す。
5. 異常系、端末復元、purge範囲、DBトランザクションを重点確認する。
6. 全品質ゲートと手動スモークテストを通し、MVPを完成とする。

共有ファイルを複数担当が同時編集しません。公開契約や依存クレートの変更は統合担当へ
集約します。

## 6. MVP受け入れ条件

以下をすべて満たした時だけMVP完成とします。

1. GitHub URLを渡すとclone、走査を経てTreeを表示できる。
2. ローカルリポジトリでも同じTreeを表示できる。
3. 対象外ファイルを選択できず、その理由を画面で確認できる。
4. ファイルを選び、正しい入力だけで最後まで完走できる。
5. 誤入力、Backspace、Enter、自動インデントが要件どおりに働く。
6. Escポーズから中断するとファイルを完了にせず、保存済み位置から次回再開できる。
7. 完走後、ResultとTreeのファイル・ディレクトリ行数進捗が更新され、途中入力の受理済み改行も反映される。
8. アプリを終了して再起動しても完了ファイルと途中チェックポイントが維持される。
9. 同じ正規化本文のファイルは行番号が変わっても完了・途中チェックポイントを引き継ぐ。
10. 正規化本文が変わったファイルの途中チェックポイントは破棄される。
11. `--purge`が確認後にアプリ管理データだけを削除する。
12. ネットワーク、入力、DBのエラーで端末表示が壊れず、修正可能な説明が出る。
13. テレメトリや打鍵データの外部送信が存在しない。

## 7. 品質ゲート

```sh
cargo fmt --all --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
```

加えて、PTYまたは実端末で次を手動確認します。

- 正常完走、誤入力表示、Backspace、Enter、Escポーズ／中断
- Treeへの途中行数進捗反映と、再起動後のカーソル・計測値復元
- clone失敗、存在しないパス、対象本文なし
- 正常終了、中断、エラー後の端末復元
- purge前の対象表示、キャンセル、実行後の範囲

## 8. MVP後の優先候補

MVP利用後に、最も価値が高いものから決めます。現時点の候補順は、refresh詳細
表示、ソート切り替え、走査中の進捗表示、`--last`、フル統計です。これは確定
ロードマップではありません。ナビゲーション再設計（D-022）は次節の対象です。

## 9. ナビゲーション再設計（D-022）

文書は確定済み。Rust実装はプロダクト要件§9を正として行い、受け入れ条件を満たす。
実装単位は次のワークストリームとする。

1. **キーマップ統一**: 場所とオーバーレイの2層へ`App`の画面状態を分け、
   `Esc` / `q` / `Ctrl-C` / `?` / `,` / `S` / `/` の意味を全画面で固定する。
   SettingsとStatsはHomeの子ではなくオーバーレイにする。Searchの`j`/`k`は
   常に文字入力にする。Homeの`s`/`c`はエイリアスとして残す。
2. **Help / Pauseオーバーレイ**: `?`で現在地のキーと記号凡例を出す。Typingの
   `Esc`はポーズ（再開 / やり直し / 中断してTree）にする。中断時はResultを
   挟まない。ポーズ中も経過時間は進める。
3. **Tree移動・絞り込み・手動除外**: `g`/`G`、`Ctrl-d`/`u`、`h`/`l`折りたたみ、
   `Tab`でおすすめへジャンプ、`/`絞り込みと`n`/`N`、`x`対象トグル、`X`手動
   上書き解除を追加する。
4. **Resultのnext / retry**: 完走時だけResultを出す。`Enter`で次のおすすめ、
   `r`で同じファイルを再挑戦、`t`/`Esc`でTreeへ戻る。次がなければ`Enter`は
   Treeへ戻りリポジトリ完了を示す。
5. **表示規約**: フッターを4〜6個、左から「主要アクション → 移動 → 戻る →
   `?` help」に揃える。動詞を`open` / `start` / `next` / `retry` / `back` /
   `close` / `quit`に統一する。現在地を上部に出す。

このワークストリームの受け入れ条件は次のとおりとする。

1. `q`を連打すると、どの場所からもHomeへ戻り、Homeで終了できる。途中の場所
   では即終了しない。
2. Treeから`,`と`S`でSettingsとStatsを開け、閉じるとTreeのまま戻れる。
3. Typingの`Esc`はポーズを開き、`t`でチェックポイントを保存してTreeへ戻る。
   ファイルは完了にならず、次回は保存位置から再開できる。`Esc`/`Enter`で再開できる。
4. Resultの`Enter`は次のおすすめを開始し、`r`は同じファイルを再挑戦する。
   次がなければTreeへ戻り、リポジトリ完了が見える。
5. Treeの`/`でファイルを絞り込み、`Tab`でおすすめへジャンプできる。
6. Treeの`x`は写経対象をトグルし、`X`は手動上書きを解除して自動判定へ戻す。
   手動上書きはrefresh後も維持される。
7. Searchで`j`/`k`を打つとクエリに文字が入る。候補移動は矢印または
   `Ctrl-n`/`Ctrl-p`だけである。
8. すべての場所とオーバーレイで`?`がHelpを開き、フッターに`?` helpがある。
9. 品質ゲート（`fmt` / `clippy` / `test`）が通る。画面描画はスナップショット
   でよく、遷移とキーの正しさはUIより下の層で検証する。

## 10. 途中進捗保存（D-023）

TypingまたはPause中は、正規化本文に対する文字カーソル、打鍵数、ミス数、累積経過時間、
セッション開始時刻、自動インデント設定を最大1秒間隔でSQLiteへ保存する。Pause、Treeへの中断、
Ctrl-C、完走では即時flushする。Treeやアプリ終了中の時間は計測せず、Pause中は計測する。

途中行数はカーソルより前で受理済みの改行数だけを数え、ファイル完走までは`todo`とする。
同じ相対パスと正規化本文ハッシュのrefreshではチェックポイントを維持し、本文変更・削除時は破棄する。
「最初からやり直し」は未完了セッションを確定してチェックポイントを削除する。
