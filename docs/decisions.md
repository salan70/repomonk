# 意思決定記録

実装上の重要な判断を追記する文書です。決定を変更する場合、古い記録を消さずに
状態を「置換済み」とし、新しい決定から参照します。

## D-001: MVPは段階リリースではなく縦切りで完成させる

- 状態: 採用
- 日付: 2026-08-11

### 決定

v0.1、v0.2のような細かな初期リリースへ分けず、次の利用ループ全体をMVPとして
一気に実装します。

`URL / ローカルrepo → Tree → Typing → Result → 進捗保存・再開`

### 理由

単一ファイルの写経だけでは、repomonk固有の価値である「実在リポジトリを
塗りつぶす感覚」を評価できないためです。AIエージェントで独立領域を並列実装し、
短い契約確定後に統合します。

### 影響

clone、走査、ファイルツリー、SQLiteはMVPに含めます。一方で体験の横幅を抑える
ため、tree-sitter、dependencyモード、詳細統計、演出はMVP後とします。

## D-002: manualモードでファイル完了後はTreeへ戻る

- 状態: 置換済み（D-012へ）
- 日付: 2026-08-11

### 決定

Resultの`r`は同じファイルに未完了チャンクがある場合だけ次へ進みます。ファイルを
完了した場合は別ファイルを自動開始せず、Treeへ戻します。

### 理由

原典のmanualモードの意図を優先し、ファイルを塗り終えた達成感と次の選択を
ユーザーへ返すためです。

## D-003: MVPの抽出は言語非依存の共通規則を使う

- 状態: 置換済み（D-012へ）
- 日付: 2026-08-11

### 決定

MVPではtree-sitterを導入せず、タブ正規化、行末空白除去、非ASCII行除外、
空行境界、5〜40行分割を全ファイルへ共通適用します。

### 理由

最初の利用ループに必要なのは安定したチャンク生成であり、言語別ラベルは独立して
後から追加できるためです。

## D-004: 生の打鍵列を永続化しない

- 状態: 採用
- 日付: 2026-08-11

### 決定

MVPで永続化するセッション情報は、開始・終了時刻、完了または中断、入力数、
ミス数などの集計に限定します。正解・誤入力を含むキーイベント列そのものは保存
しません。

### 理由

写経アプリのキーイベント列は、実質的にキーロガーと同じ機密性を持ちます。詳細な
統計に不要な生データを最初から保持しないことで、漏えい時の影響とpurge対象を
小さくします。

## D-012: 写経単位をファイル全文とし、進捗は行数で集計する

- 状態: 採用
- 日付: 2026-08-11
- 置換: D-002、D-003

### 決定

- 写経の最小単位はチャンクではなく、対象ファイルの正規化済み全文とする。
- Treeでファイルを選ぶと、チャンク一覧を出さず直接Typingを開始する。
- 空行境界や `min_lines` / `max_lines` による分割は行わない。
- Esc中断ではファイルを完了にせず、次回はファイル先頭から開始する。
- ファイル完了後は別ファイルを自動開始せず、Treeへ戻る。
- 進捗の分母・分子は正規化済み行数とする（完了ファイルの行数合計 /
  対象ファイルの行数合計）。
- refresh時の完了引き継ぎは、ファイル全体の正規化本文SHA-256で行う。
- 永続化は当面 `chunks` 表を流用し、ファイルあたり常に1レコードとする。

### 理由

ユーザーがファイル単位で開いて打つ体験を優先し、チャンク選択の画面遷移をなくす
ためです。進捗の塗りつぶし感は、チャンク個数より行数の方がファイルサイズの差を
反映できるためです。

### 影響

- D-002の「次チャンクへ進む`r`」は不要になる。
- D-003の空行境界・5〜40行分割は採用しない。正規化規則自体は維持する。
- 既存DBに複数チャンクがある場合、再スキャンでhash不一致となり完了が落ちうる
  （ローカル進捗の破壊的変更を受け入れる）。
