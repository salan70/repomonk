# TUIガイドライン

状態: 採用（D-031）。

ユーザーから見える挙動の正は [product-requirements.md](product-requirements.md) です。
この文書は見た目と実装の寄せ先です。画面を足す・直すときはここを先に読み、
新しい区切りグリフや配色を発明しないでください。

## 1. 寄せ先

- 配色・枠・区切り・キーヒント: `src/ui/theme.rs`
- ユーザー向け文言: `src/ui/i18n.rs`（日本語既定、英語併記）
- 画面の役割とキー: [product-requirements.md](product-requirements.md) §9

## 2. 区切り

データ欄とキーヒントは別系統です。どちらにも中黒 `·` / `・` を使いません。
ASCII `|` や別グリフを新設しません。

| 用途 | 使うもの | 例 |
| --- | --- | --- |
| ヘッダ、サマリ、詳細、ステータス行 | `theme::FIELD_SEP`（文字列）または `theme::field_sep()`（Span） | `12%  │  3/48 files` |
| フッタのキーヒント | `theme::key_hints`（空白区切り） | `Enter 開く   j/k 移動` |

画面側に `│` を直書きしません。Typing のステータス行も `field_sep()` を使います。

Typing だけはフッタ行を持たないので、1 行に 2 系統が同居します。左にデータ欄
（`field_sep()`）、右端にキーヒント（`key_hints`）を置き、間を空白で埋めて右寄せ
します。連結してはいけません。`│` のうしろにキーヒントを続けると 2 系統の区別が
壊れます（D-033）。

### 例外（区切りではない）

- 対象外ファイルの行頭マーク `·` と Help 凡例（`✓` / `◐` / `○` / `·`）
- 複合語の「設定・ドキュメント」（前後に空白を付けない）
- パス区切りの `/`、現在地の `›`、対象外短ラベルの `—`

## 3. 画面を足すとき

- フッタは `theme::key_hints` にキーと動詞の対を渡す。件数と語順は PRD §9.4。
- ステータスや数値の並びは `FIELD_SEP` / `field_sep()` でつなぐ。
- 幅が足りないときはキーヒントを段階的に落とす。データ欄を先に削らない。
- 枠とタイトルは `theme::bordered_block` と `theme::title_line`。
- ユーザー向け文字列は `i18n.rs` のカタログへ置く。描画関数に日本語や英語を埋め込まない。
- 配色は `theme.rs` の Tokyo Night 定数だけを使う。

`src/ui` のソースにスペース付き中黒（U+00B7）が含まれるとテストが失敗します。
